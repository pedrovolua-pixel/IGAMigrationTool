# Synthetic draft report projection

`DraftSnapshotBuilder.Build(DraftReportInput)` creates one detached, immutable JSON value for the approved local cycle06 draft. `SyntheticDraft` is unpublished and the source run remains `Scoring`. The input is a server-created, already-authorized projection; this pure module does not retrieve evidence, authorize a caller, persist a report, resolve a reference or grant publication. Digests identify values and are not permission.

The source binds the fixed fictional scope, run/revision/input, complete frozen version tuple, capability and analysis locks, saved coverage, current scoring, analysis, captured review and independent maturity digests. The full schema/status/source/content envelope is SHA-256 hashed; the digest itself is excluded. JSON properties use ordinal order, numeric tokens use invariant decimal representation. Fixed version and required-data guards refuse an unavailable/malformed source rather than build a simpler fallback.

Declared set arrays normalize by stable ID: health categories/object types/modules/outcomes, findings, maturity domains and capability modules. Review groups normalize by finding ID. Healthy controls and coverage limitations normalize by object/rule tuple. Duplicate declared IDs, duplicate JSON properties, maturity gate/indicator kinds and event UUIDs within a finding refuse. All other arrays retain order, including attributed history events and prose/evidence references. History revisions are contiguous and the captured final state/title/context must match current finding presentation. Maturity nested data is structurally validated; scoring and maturity algorithms remain owned by their existing modules.

Input JSON is cloned, including all three source locks, and survives disposal of caller documents. Returned bytes belong to the caller. `ValidateSnapshot` revalidates bindings and the full envelope and refuses changed or noncanonical records. Text is stored as text; inert Markdown rendering belongs to the separate `StructuredDraftMarkdown` implementation. Content excludes actions, tokens and observation time. The synthetic implementation bounds JSON to 32 MiB and depth 32; it is not a production reporting schema or durable history.

Focused checks use manually authored primitive fixtures and literal source/state/status expectations, source binding changes, malformed/duplicate data, history coherence, culture, document disposal, caller mutation, returned-byte isolation and 100 deterministic random ordering permutations. No database, transport, browser, PDF, export or publication check is claimed by the pure module. No dependency, migration or configuration change is required.
