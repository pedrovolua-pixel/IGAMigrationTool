# Synthetic deterministic analysis module

This cycle-04 internal module executes five fixed typed count predicates over value-free synthetic fixture markers. It contains no actual One Identity logic, source reader, catalog promotion, customer authority, AI, maturity, review mutation or remediation executor. All fixture conclusions explicitly disclose this limitation. Product/technical/test authority is feature 003 and the canonical `plans/active/local-pilot-analysis-scoring-cycle-04.md`.

The catalog contains `SYN-GUARD` (Critical) and `SYN-TRACE` (High) in `SECURITY` / `SyntheticSecurity`, and `SYN-PENDING` (Medium), `SYN-DUPLICATE` (Low), `SYN-UNUSED` (Informational) in `OPERATIONS` / `SyntheticOperations`. Object type is `SyntheticControl`. Two fixed objects per module produce ten distinct `CoverageKey(ObjectId, RuleId)` units. Health category differs from evidence-category key. No approved desired outcomes are fabricated: every outcome list is empty.

Each rule requires its typed count fact. Exact compatible known count above zero yields Finding, zero yields Pass. Missing/conflicting/invalid counts, redaction, exclusion, incompatible versions and type/module mismatch yield explained terminal states. Critical/High originals are Proposed; lower severities are AutoConfirmed only because each exact catalog entry explicitly permits it. Confidence is 100 percent with the fixture-only band `Deterministic synthetic evidence`; it is distinct from severity and does not measure real-world certainty.

`SyntheticAnalysisFixturePack.Freeze(scope,presetId,profileId)` accepts only the existing fixed synthetic scope triple. Baseline IDs are `synthetic-analysis-{healthy,findings,gaps,mixed}-v1`. Profiles are `synthetic-analysis-equal-v1` (Security/Operations .5/.5) and `synthetic-analysis-operations-v1` (.25/.75), version `synthetic-profile-v1`, algorithm `pilot-health-v1`, gaps excluded from health. All four baselines opt into these new profiles. Existing coverage-only presets and profiles are outside this module.

`SyntheticAnalysisEngine.Plan(frozen)` evaluates trusted fixture facts, freezes units and typed results and returns expected coverage for durable work. `Analyze(frozen,runId,savedCoverage)` accepts only a complete reconciled canonical saved coverage set, with exact state/reason/stage/evidence-reference equality to evaluated fixture results; no partial or caller-invented result can produce findings. Host integration must additionally require complete saved coverage and frozen optional metadata on the actual durable run. This module neither reads nor changes run lifecycle.

Empty run IDs are rejected. Occurrence identities bind the exact run ID; stable root-cause keys remain scope/rule/version/root-cause based across runs. Every generated original includes run/rule/catalog/pack/evidence/scope compatibility provenance, one typed observed fact, inference, assumptions, separate severity/confidence, impact/likelihood, root cause, inert options, validation guidance, limitations, review policy and its digest. Read-only immutable arrays retain every object/unit occurrence even when a stable rule/root-cause key groups their presentation. This is a generated original, not a mutable current review revision. No disposition alone establishes closure.

Digests use the internal v1 canonical JSON writer: ordinal object-property order, significant array order, invariant .NET JSON number representation, UTF-8, SHA-256 lowercase hex. Whole-pack content includes every rule field, every baseline fact/reference/metadata, every profile field/weight, exact compatibility, scope and engine version, confidence and explicit boundary metadata. Catalog, evidence, profile and frozen-input digests are checked independently. Saved results are sorted by rule/evidence-category then object ID before digesting. A generated-original digest hashes its record with `GeneratedOriginalDigest` set to the empty string; analysis content digest likewise hashes its record with `ContentDigest` empty. These private canonical bytes are not a public protocol or production signature decision.

No external dependencies are added; only the existing AssessmentCoverage project is referenced. Coordinator owns solution/CI/project wiring, persisted frozen optional metadata, host/API/frontend and canonical implementation/evidence records. This module requires no migration or configuration change. Unit tests are an executable repository-style assertion host and cover all five fixture classes for every rule, additional gaps, immutable originals, root-cause occurrence preservation, full lock/content mismatch denial and saved-coverage reconciliation. Live rule promotion, human SME/security/product review, actual outcome approval and broader Phase 1B acceptance remain unverified.
