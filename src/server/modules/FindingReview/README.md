# Synthetic finding review store

This module implements only the explicitly approved cycle-05 local review/history packet. Its authority is `plans/active/local-pilot-review-maturity-cycle-05.md`, feature-003 product/technical lifecycle and the approved authorization matrix. It does not implement production identity, customer routing, risk acceptance, remediation/closure, recurrence, mentions, notifications, attachments, publication or source-system changes.

The host supplies the fixed `SyntheticReviewScope.Fixed` triple and a disclosed typed synthetic actor. HTTP input must never supply actor, roles, scope, categories, grants or seeds. Policy checks authenticated/active/nonrevoked identity, active exact assignment, Consultant or QualifiedReviewer role, explicit action grant, category and mutable resource state. QualifiedReviewer presentation changes require the explicit EditPresentation grant. Only Confirm/Reject/Defer from Proposed, inert comments, and bounded presentation edits exist. Reject requires a nonblank reason. Reason/comment/business-context lengths are at most 2000 UTF-16 code units; presentation title at most 250. Empty business context explicitly clears that field. Unsupported event kinds, extra per-kind fields, absent grants and nonmutable resources fail closed. There is no operation that changes resource availability or creates Reopened state.

`SyntheticReviewStore(connectionString,trustedScope,observer?)` accepts only the exact fixed synthetic scope and loopback `iga_synthetic_` databases. `InitializeAsync` applies/verifies the separately owned `synthetic_review` schema. `SeedAsync(SyntheticReviewRunSeed,authority)` is a trusted internal host operation after the host verifies canonical complete saved run/analysis and the new opt-in profile. It requires the synthetic Consultant with Read and Review grants, never a client seed-write permission. The seed binds run ID, scope, exact input and analysis digests, original title/initial Proposed or AutoConfirmed state, original digests and rule/object/occurrence references. Seeds normalize ordinal finding/occurrence/digest order. Exact replay is idempotent; changed content conflicts. Digest shape alone does not establish upstream analysis integrity: the host must validate the source before supplying seeds.

`ReadAsync(scope,runId,authority)` reads all authorized findings/current projections/ordered history in one repeatable-read transaction. Missing category authority denies the whole snapshot, preserving a coherent scoring overlay rather than silently dropping units. SnapshotDigest binds the complete run seed, every current projection and every event; it hashes the snapshot with SnapshotDigest empty. Nested collections are immutable arrays. Every stored original/event digest, event chain and current projection is checked before returning facts.

`ApplyAsync(scope,runId,findingId,authority,command)` locks that finding's current row, checks the category/resource policy, and appends its event plus current update atomically. Initial revision is 0. Command event UUID is namespaced by run/finding. Identical command and actor replay returns the original event outcome/revision even after later comments/edits; a changed payload/actor conflicts. Replay does not bypass current revocation or action/category checks. A stale revision is checked before a now-invalid transition and returns RevisionConflict without a write. The caller should then read a fresh whole snapshot for coherent UI/current-score projection; the returned replay outcome is intentionally historical. Actor ID/roles and PostgreSQL UTC clock time accompany every appended action. No command rewrites the generated originals or occurrence references.

Migration ID is `synthetic-review-001`; embedded SQL SHA-256 is `f919f6a16de9a579573e52046ca1d756f691dfed5f79c1d6eda5ecc7b370180d`. The schema contains migration metadata, immutable scope/run/finding seeds, current projections and append-only events. Foreign keys retain scope/run/finding association. UPDATE/DELETE/TRUNCATE triggers protect originals, scope, migration records and history; current updates must advance one revision and match an appended event. Migration content and a schema fingerprint (columns, constraints, indexes, trigger definitions/enabled states and functions) are verified at initialization and on each operation. Unknown/untracked schema and drift are refused. A database owner capable of altering triggers/records is outside the trusted synthetic application boundary; this is not production database-role hardening. The existing assessment schema/migration is untouched. Rollback disables the new profiles/write routes or uses a compatible reader; it preserves these records and performs no destructive down migration. Retention/customer policies remain outside this bounded implementation.

SHA-256 uses private canonical UTF-8 JSON with ordinal object-property order and significant normalized array order. Event payload identity binds private schema version, scope, run/finding, actor ID and all command fields. Original digests are trusted upstream immutable references, not signatures or promotion evidence. No comment/text is executed, logged or used as an instruction.
