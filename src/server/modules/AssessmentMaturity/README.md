# Synthetic capability maturity

This cycle-05 internal module implements the approved cumulative `pilot-maturity-v1` algorithm over fictional mandatory-domain indicator evidence. Its authority is feature 003 and `plans/completed/local-pilot-review-maturity-cycle-05.md`, explicitly approved by the repository owner. It has no health input, scoring dependency, source reader, review mutation, catalog promotion, production validation or publication operation. Synthetic evidence/ownership flags establish no actual customer authority.

`PilotMaturityProjector.Project(MaturityInput)` returns either a typed issue with no projection or an immutable maturity projection. Every declared domain is mandatory. All declared mandatory domains remain in every denominator, including domains with partial or missing evidence, as approved for this packet. An empty/invalid catalog exposes no projection. Missing indicators become explicit `InsufficientEvidence` entries with `MISSING-SYNTHETIC-INDICATOR`; their domain never disappears from the denominator.

Each domain has Design, Implementation, MeasuredOperation, RegularReview and ValidatedImprovement indicators. Known Met, PartiallyMet or NotMet states require nonblank evidence references; InsufficientEvidence requires a reason. Only Met counts toward a gate. Developing requires paired design/implementation in at least 60% of domains. Defined additionally requires at least 80% base domains and explicit Met governance ownership with an owner and evidence. Managed additionally requires paired measured operation/regular review in at least 80%. Optimized additionally requires Met explicitly validated improvement with at least two distinct nonblank assessment references in at least 80%. Preceding levels are global prerequisites; base, operation/review and improvement domain sets may differ. There is no additional intersection requirement. One assessment repeated twice counts once and cannot establish Optimized.

The catalog freezes algorithm thresholds 60/80/80/80, the two-assessment minimum, domain identifiers/names and the explicit synthetic authority boundary. Unknown algorithms/schemas, malformed metadata, duplicate domain/indicator keys, unknown domains, invalid states/references, missing known-state evidence, unvalidated Met improvement and malformed ownership fail closed. Threshold comparisons use integer ratios without rounding. The projection retains all normalized input evidence/reasons, domain achievements, gate numerators/denominators and prominent partial/negative/insufficient counts. Improvement marked Met without enough distinct assessments remains visible but does not count toward Optimized; its shortfall has a separate count. Ownership state and its evidence remain visible independently.

`SyntheticMaturityFixturePack.Freeze(baselineId, sourceAnalysisFixtureDigest)` accepts the four existing cycle-04 baseline IDs and a valid lowercase SHA-256 analysis-fixture digest. It returns the whole immutable input and its canonical input digest as `ContentDigest`, which the coordinator freezes with the run's other inputs. The five fictional domains are not actual One Identity domain definitions. Healthy maps to Initial with 25 missing indicators, findings to Managed with five single-assessment improvement shortfalls, mixed to Developing with three of five base domains and 19 missing indicators, and gaps to Initial with 25 missing indicators. These examples deliberately demonstrate independence from health.

Every collection, including evidence/assessment references and domain definitions, is snapshotted into read-only arrays. Ordinal domain/kind/reference ordering and exact-reference deduplication produce deterministic projections across caller reordering. Internal versioned length-prefixed UTF-8 SHA-256 digests bind source analysis digest, all version/catalog/threshold/boundary metadata, full indicator evidence, validation flags, owner/reasons, level and projected counts/gates. The input digest binds the normalized explicit missing indicators. These digests are reproducibility metadata, not signatures, integrity verification of customer evidence, or authorization tokens; the coordinator validates the frozen source/run tuple before projecting.

There are no external packages or project dependencies, migrations or configuration changes. Shared solution/CI wiring, host/UI, compatible run-input metadata, canonical records and private status-site publication belong to the coordinator. Historical cycle-03/04 runs do not acquire maturity implicitly.
