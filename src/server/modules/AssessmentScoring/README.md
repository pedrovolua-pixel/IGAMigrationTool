# Synthetic pilot health scoring

This internal cycle-04 module implements the approved `pilot-health-v1` health formula over trusted, value-free synthetic rule/subject units. Its authority is feature 003 and `plans/active/local-pilot-analysis-scoring-cycle-04.md`. It does not calculate maturity, call an AI provider, grant approval, change review state, promote a catalog, publish results or advance run lifecycle.

`PilotHealthScorer.Project(ScoringInput)` returns a typed denial or an immutable `ScoringProjection`. The bounded input has exactly one unit per unique `CoverageKey`; the key may identify a rule/object pair while health category is a separate field. Expected keys and terminal coverage must reconcile completely, and every unit must match its coverage state. The caller validates the actual frozen analysis/catalog/profile content before calling; syntactically valid digest references alone do not establish source integrity or authority. Empty eligible sets have unavailable scores, never an assumed passing result.

Catalog weights must be positive. Severity penalties are Critical 1, High .8, Medium .45, Low .2 and Informational 0. Deterministic confidence has factor 1; the pure AI fixture factor clamps locked confidence percent / 100 to [.5, 1]. Pass and Rejected earn full unit weight. Every Proposed finding contributes only to provisional health; retained-penalty lifecycle states keep their penalty. AI and Critical/High deterministic findings cannot be AutoConfirmed. ValidatedClosed requires an explicit Pass, a passing-evidence flag and a nonempty synthetic evidence reference. A raw Finding with that disposition is denied. These flags and references are trusted fixture metadata, not a real validation or approval operation.

Category health is `100 * earnedWeight / applicableWeight`. Overall health uses unrounded assessed-category means: equal weights or a fixed explicit positive profile whose weights sum to 1. Unassessed categories are excluded and the remaining weights renormalized. Object type, module and explicitly approved fixture outcome projections each use their own unit-weighted subset. Multiple outcome links and grouped presentation do not duplicate overall units. Outcome approval flags express only a synthetic test premise. Gaps and NotApplicable contribute no health weight; separate quality retains coverage counts, limitations, executable coverage, method counts, review counts and execution failures. This quality subset does not supply an overall blended-health score.

All arithmetic is decimal; intermediate overflow fails with `NumericOverflow`. Raw scores determine Red below 50, Yellow below 80, otherwise Green. Only display values round to one decimal with `MidpointRounding.AwayFromZero`, the settled cycle-04 display convention; rounding never changes raw category averaging or status.

The returned projection snapshots every collection, including nested outcome links and profile weights, into read-only arrays. Ordinal sorting removes caller ordering differences. Its SHA-256 lowercase hex digest uses internal versioned length-prefixed fields and invariant canonical decimal strings, binding frozen version/digest references, full coverage, unit/lifecycle/evidence metadata, profile weights, outcome flags and both score sets. These canonical bytes are a private fixture contract, not a public signature protocol.

No external packages, migration or configuration changes are required. The sole project dependency is the existing AssessmentCoverage module. Shared solution/CI wiring, host integration, canonical plans/evidence and the private status site belong to the coordinator.
