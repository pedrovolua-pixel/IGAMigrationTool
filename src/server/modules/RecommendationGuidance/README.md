# Synthetic recommendation guidance

`RecommendationGuidanceBuilder.Build(GuidanceInput?)` derives one detached read-only value from host-created, already-authorized and engine/review-validated fictional data. The module has no project/package reference, database, resolver, authority, network, renderer or executor. It does not resolve protected references, promote a catalog, create tasks, export artifacts or establish customer remediation. The settled records remain in `GuidanceContracts.cs`.

The fixed schema is `synthetic-recommendation-guidance-v1`, status `SyntheticUnverified`; every option is `Unverified`. A current finding Confirm/Reject/Defer never constitutes recommendation review or validation. Every original option survives those decisions. Empty findings are valid for healthy/gaps-only input; no advice is fabricated. Original title/occurrences/digests/references and current presentation/business context/state/revision remain separate. There is no durable recommendation version/history or terminal assessment/publication transition.

## Source and denial boundary

The source must name the fixed fictional customer/project/environment, nonempty run UUID, nonnegative matching run/review revision, Scoring state and one existing review/maturity profile/baseline. All source digests are lowercase 64-hex identifiers. Frozen versions, capability and analysis locks reject missing/unknown/duplicate fields, including nested scope/compatibility/modules. The current fixed versions, two synthetic modules, their versions and compatibility 160 must match; source baseline/profile/scope/catalog/analysis-fixture links must agree. Capability modules have unique IDs. Source digests bind the supplied value and never grant permission.

Finding IDs and original occurrence/digest identifiers must have 64-hex shape; finding, occurrence and per-finding object/option IDs cannot duplicate. Occurrence IDs are unique across all groups; repeated option IDs in separate groups are legal. At least one occurrence/option/validation/reference/limitation is required per finding. Ordered assumptions can be empty, never default. Current/initial states are limited to existing synthetic review states. AutoConfirmed remains AutoConfirmed; Proposed cannot become AutoConfirmed; severe findings begin Proposed. Revision 0 retains initial title/state and empty business context. Unknown rule version, category, severity, object type or module are denied. A failure returns a typed issue and null snapshot; no simplified or stale output is constructed.

The host must establish that the supplied generated originals, grouping, descriptors and current review are the canonical saved source. This module receives no complete review history or rule fact record, so it cannot prove an arbitrary source/original digest, actor authority, rule/root-cause semantics or review transition merely from hash shape. Those upstream checks are not replaced by local projection validation.

## Canonical bytes and identities

`CanonicalPayload(snapshot)` returns independent UTF-8 bytes, no BOM/newline, for the complete object containing `schemaVersion`, `status`, `source`, `findings`, `warnings`, `unavailableSections`. `contentDigest` is excluded. Keys recursively sort by ordinal comparison, names use camelCase (`JsonSerializerDefaults.Web`), JSON strings use default `System.Text.Json` escaping, and decimal numeric tokens use invariant `G29`. UUIDs use lowercase D format. Null remains explicit null. Findings sort by FindingId, occurrences by OccurrenceId, options by OptionId and capability modules by id. Ordered guidance/reference/assumption/limitation/warning/unavailable arrays retain order. The snapshot clones/canonicalizes all source JsonElements and uses immutable typed collections.

ContentDigest is lowercase SHA256 over those bytes. ScopedOptionId is lowercase SHA256 over the contract's exact canonical object `{findingId,optionId,runId,scope:{customerId,environmentId,projectId}}`, recursively ordinal property order, no BOM/newline. Its identity binds fixed scope/run/finding/option, independently of current review/presentation; it is never a grant. IDs can repeat between different source snapshots when the same option identity persists.

Local fixture guards are 32 MiB canonical bytes, depth 32, 16 Ki UTF-16 code units per text field and 100,000 findings/occurrences/options or text-array entries. They are implementation bounds, not a customer retention, export or security policy. Text arrays preserve all declared ordered data; supplied HTML/Markdown/script/formula/shell/network text remains data. The UI must render it as encoded inert text and cannot resolve references or introduce execution/export/review controls.

## Portable evidence

The executable unit host owns manually authored primitive JSON/records and an independently authored exact golden byte fixture. Literal scoped-option and full-envelope hashes were calculated with a separate Python standard-library canonical JSON/SHA256 script from those explicit records, not from the module helper. Tests verify the exact byte fixture, source/content changes, stable original/current identities, all supported states, empty advice, repeated cross-group option IDs, denial shapes, duplicates, hostile text, document disposal/caller-array changes and source/key ordering. The golden JSON intentionally has no trailing newline because it is a byte fixture.

These portable checks do not execute database, transport, browser, task/CSV/PDF, accessibility, production policy or publication behavior. Coordinator/independent packets supply their separately executed evidence. This bounded slice does not complete Milestone 7, Phase 1B or G1–G9.
