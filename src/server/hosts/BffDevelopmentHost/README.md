# Hard-disabled BFF development host

This executable composes the reviewed BFF foundation and actual PostgreSQL session-store dependencies for package preparation. **It cannot be activated as a production BFF.** It has no login, logout, token, session or customer route. It never provisions subjects, migrates databases, opens SQL or issues cookies. Every ticket operation refuses through a decorator around the real store; subject and session admission always deny. The existing disabled framework callback guard and an unconditional refusing HTTP backchannel prevent provider processing/network requests.

Start only with `--bff-development-disabled` and explicit runtime environment inputs `IGA_BFF_TENANT_ID`, `IGA_BFF_CLIENT_ID`, `IGA_BFF_MANAGED_IDENTITY_CLIENT_ID` (distinct supported GUID identities), and `IGA_BFF_CONTROL_PLANE_CONNECTION`. Supply actual deployment bindings outside Git when authorized; do not put identifiers, credentials or connection strings in recipes, build arguments, documentation or logs. The connection configuration is parsed to compose the store but is never opened. Missing/invalid inputs and activation/proxy flags refuse startup with a fixed small message. Arguments are exact; all other flags refuse.

The DI-wide **ephemeral Data Protection provider is permitted only because this executable is permanently disabled and never issues tickets/cookies**. It writes no key files. It is not shared, recoverable production key storage. A future separately reviewed production host must require the protected shared ring and trusted session-bound authorities; it cannot enable this diagnostic executable by supplying a flag. No environment/file/CLI setting can switch `LiveSignInEnabled` to true.

The fixed HTTP 8080 listener exposes only the already approved bootstrap probes: exact `GET /health/live` returns 200 `{"bootstrapOnly":true}`; exact `GET /health/ready` returns 503 `{"code":"product_not_enabled","bootstrapOnly":true}`. Liveness establishes only process presence. Other application targets return 404; exact disabled framework callbacks return 403 before protocol work. Query, encoded, alternate-case and alternate-method probe requests are refused. No forwarded headers are trusted. Responses are no-store, with no provider/identity detail, cookie or redirect. Configuration and log providers are cleared; exceptions/environment/request content are never dumped.

Container recipe and immutable MCR base lock: `infra/containers/bff-development.*`. Runtime uses UID 1654 and no committed runtime configuration. Dockerfile-specific context includes only exact required module/host source, locks, shared build settings and embedded additive migration bytes; the migration is not executed. The local build helper never pushes an image. Docker-capable CI must execute the real non-root/read-only smoke and the separately prepared image evidence collector before package evidence can be claimed. Azure resources, release promotion, accepted provenance and live identity tests remain separate.
