## Source format and validation

Source port has separate authorized manifest and item reads: `ReadManifestAsync(scope, assessmentId, reportVersionId, token)` returns an immutable `ManifestSource` envelope with original canonical UTF-8 bytes and declared original SHA256 digest, or null; `ReadItemAsync(scope, reportVersionId, kind, itemId, token)` returns minimized fictional payload UTF-8 bytes or null. No raw-evidence resolver, arbitrary locator or fallback exists. Deny resource authorization before manifest read. Validate manifest metadata completely, then select only category/field-authorized descriptors before loading payloads. Validate every selected payload before emitting a response; never fetch denied-category content to validate or redact it. Digests of unrequested payloads remain frozen manifest commitments, not a claim that inaccessible content was read/verified.

Manifest exact closed keys: `contractVersion`, `fixtureKind`, `customerId`, `projectId`, `environmentId`, `assessmentId`, `reportVersionId`, `baselineVersion`, `catalogVersion`, `scoringProfileVersion`, `maturityProfileVersion`, `applicationVersion`, `assessmentState`, `approvalState`, `collections`, `items`. Version `synthetic-published-health-read-v1`; fixture `SyntheticPublishedFixture`; assessmentState `Completed` or `CompletedWithGaps`; approvalState `SyntheticApproved`. These fictional labels cannot authorize actual publication. All IDs and version strings match ASCII `syn-[a-z0-9-]{1,64}`. `items` is an array of exact descriptors `kind`, `itemId`, `category`, `payloadDigest`. The required `collections` array lists exactly all six kind names in enum order; collection groups may have zero descriptors. PublishedStatus and Scores have exactly one descriptor each; other groups may be empty. Categories: `Summary`, `Configuration`, `Identity`, `Operations`. Descriptor `(kind,itemId)` unique, itemId scoped to its kind, SHA256 lowercase64hex; descriptor order is kind enum order then ascending ordinal itemId. No undefined enum/numeric enum aliases.

Canonical UTF-8 format: objects sort property names ordinal; compact no whitespace/BOM/trailing newline; strings use raw UTF-8 except JSON-required escapes, numbers are finite decimal normalized with invariant `0.############################` (no exponent or negative zero); arrays retain specified order. Reject duplicate/unknown properties recursively, over-depth16, source manifest>1MiB, descriptor count>10000, individual minimized payload>65536bytes, noncanonical bytes and digest/shape/scope/version mismatches. Manifest digest is SHA256 of the exact canonical bytes, external to those bytes. Compare the declared source original digest and trusted grant ManifestDigest against recomputed bytes before parsing/projection; computing a new digest from potentially altered bytes alone never authorizes a changed publication. Payload hashes independently bind canonical payload bytes. The verifier pins a Python-authored ASCII canonical golden before implementation and tests Unicode request/response byte accounting independently.

## Resource payloads

Every payload is a closed object with required `itemId`, `category` matching its descriptor plus the exact kind fields below. Optional output fields are omitted only by current field policy; source fields are all required. No nullable/missing source field acts as a fallback.

| Kind | Exact additional source fields |
| --- | --- |
| PublishedStatus | `assessmentState`, `approvalState`, `limitations` (allowlisted reason strings) |
| Coverage | `assessed`, `gap`, `unavailable` (nonnegative integers<=100000), `label` (minimized safe text), `limitations` |
| Scores | `health`, `quality` (decimal0..100 or JSON null with explicit `Unavailable` reason), `maturity` (integer1..5 or null), `reason` |
| Findings | `title`, `summary` (minimized safe text), `severity` (Critical/High/Medium/Low/Informational), `reviewState` (Proposed/Confirmed/Rejected/Deferred), `confidence` (High/Medium/Low/Unknown), `mandatoryReview` (bool), `referenceIds` (scoped fictional ID array, unique) |
| Recommendations | `findingId`, `summary`, `options` (safe-text array), `priority`, `effort` (safe-text), `reviewLabel` (Unverified/SyntheticReviewed) |
| ProtectedReferences | `availability` (Available/Unavailable/Redacted), `reason` (safe reason enum) |

Safe reasons: `None`, `DeclaredGap`, `Unavailable`, `Expired`, `Redacted`. If any score/maturity is null, reason is exactly Unavailable; if all are present, reason is None or DeclaredGap. PublishedStatus state/approval must equal manifest fields. No source number recomputation. Text is deliberately fictional and closed: exact atoms `Fictional finding.`, `Fictional summary.`, `Fictional coverage.`, `Fictional recommendation.`, `Fictional option.`, `Fictional priority.`, `Fictional effort.`, `Fictional résumé.`; text may be one atom or repeat the *same* atom separated by a single ASCII space, maximum4096characters. This is a fixture minimization vocabulary, not a production free-text sanitizer. All IDs, reasons, enums and text are validated before serialization. Unknown prose/sentinels cause whole requested projection denial, including nested options. Findings.referenceIds must exist among same-manifest ProtectedReferences descriptors; Recommendations.findingId must exist among Findings descriptors. Validate linkage without referent content reads. Filter referenceIds whose referent category is denied; omit recommendation findingId when its referent category is denied. No cross-scope or unproven IDs survive. Original manifest bindings are never derived from filtered content.

Protected reference `availability` and `reason` stay frozen in the payload. Trusted policy port `ReferenceAvailability(scope,reportVersionId,itemId)` supplies a separate current enum/reason overlay appended as `currentAvailability`/`availabilityReason` only to authorized ProtectedReferences results. A current non-Available overlay never enables resolution/restoration; an overlay cannot change manifest hash or historical fields.

## Policy and atomic emission

Trusted caller context contains server-created identity kind/ID (NamedUser/Service/Anonymous/ShareLink/Support/Workload) and correlation UUID. Client request is a UTF-8 JSON byte array only. Host policy port receives caller, requested assessment/report and parsed resource; it returns current immutable `ReadGrant` or null. A grant includes trusted scope, identity/security revision, booleans active identity/assignment/customerMcpPolicy/resourceAvailable/readBlocked, category set and per-kind field allowlist. No UI role alone satisfies a grant. Non-read-blocking retention holds are represented with readBlocked=false. Invalid/unsupported kinds never receive authority.

Policy port also supplies `TryCommit(grant, action)`: under one trusted test-host synchronization fence it compares all current authority/state revisions, executes the supplied safe audit/emission bookkeeping only if current, then returns true. B uses this fence for final audit/cursor registration/return-result construction; revocation that wins before this fence gives no content. It is a synthetic atomicity port, not production authorization proof. The synthetic fixture implementation locks assignment and emission consistently; production adapter remains absent. Audit cannot wait asynchronously under this fence. Source reads and payload validation happen outside it and honor cancellation/deadline.

A grant permits exactly one kind and finite safe field names. Unknown schema field names from a trusted test port cause dependency denial and cannot be echoed to audit. Grant identity/kind/scope/request bindings must match the trusted caller and requested IDs. Its revision includes identity/assignment/customer policy/resource lifecycle and reference-availability changes; TryCommit stale failure records one generic unavailable event with no scope/content. Recheck cancellation and deadline inside the emission fence before audit/cursor/result construction. Always include itemId/category for an authorized row; optional visible kind fields come from the allowlist. Nested options/reference IDs inherit category/projection minimization and field permission. Audit reports returned/redacted *schema field names*, never property values or unknown raw strings. Correlation UUID comes from caller, not raw request. Identity and scope are recorded only from safe validated context/grant; no raw request ID echo on denial.

## Request, result, audit

Request closed fields exactly from approved proposal. ResourceKind names are exact case-sensitive names above; caller supplies no method aliases. Only collections Coverage/Findings/Recommendations/ProtectedReferences accept pageSize/cursor; PublishedStatus/Scores reject either. Default25/range1..100. ContractVersion exact; assessment/report IDs exact fictional grammar. Duplicate/unknown/nested/invalidUTF8/oversize>16384bytes/undefined kind yield `InvalidRequest` (unknown method only safe UnknownOperation audit; no echo). An unknown/unpermitted method has zero source reads/business writes. Null authority gives generic `Unavailable`.

`McpResult` has outcome, nullable serialized envelope bytes, nullable cursor handle; non-success carries neither payload nor cursor. Reference schema field vocabularies include currentAvailability/availabilityReason as explicit overlay fields. Enum serialization is exact case-sensitive string names. Successful canonical response closed keys: `contractVersion`, `resourceKind`, `manifestDigest`, `bindings` (all frozen manifest scalar bindings including fixture marker), `items` (authorized field-filtered canonical objects), `nextCursor` (string/null). bindings is flattened into the manifest scalar keys contractVersion, fixtureKind, customerId, projectId, environmentId, assessmentId, reportVersionId, baselineVersion, catalogVersion, scoringProfileVersion, maturityProfileVersion, applicationVersion, assessmentState, approvalState; no nested Scope, PascalCase record keys, collections or descriptors. It never includes total counts of unauthorized items. Envelope byte budget262144 includes cursor/bindings/multibyte strings. Cursor randomness is real32byte crypto RNG; opaque lowercase64hex string; SHA/authority values cannot serve as handles. Cursor token is held only in local memory. Audit event contains safe caller kind/ID where valid, grant scope where authorized, enum resource or null/UnknownOperation, schema fields/redacted field names, typed outcome, correlation UUID and nonnegative elapsed monotonic milliseconds. No payload bytes, hashes of hidden values or locator strings.

Every invocation attempts one completion audit (including malformed/denied/limited/cancelled); duplicate internal delivery of one invocation does not duplicate audit. A distinct call/retry is a distinct event and new policy evaluation. Audit false/throw yields DependencyUnavailable, no content or cursor, plus a safe operational failure enum via the audit port. No false success if cursor capacity reservation or audit fails. Source/policy exceptions and timeout give typed outcomes without exception text. Cancellation preempting processing gives Cancelled;5second deadline gives DependencyUnavailable; no throw across harness boundary. Separate per-request bookkeeping records audit once.

## Limits, clock, cursors

Use TimeSpan-valued monotonic clock port; B clamps observations to a nondecreasing high-watermark under one synchronization lock. Reject nonfinite/negative test clock; clock failure denies dependency. Request rolling admission windows store bounded timestamps, evict only age>=60seconds; local budgets60identity/300customer, concurrent4identity/16customer. A denied request with resolved grant/identity still consumes admitted budget; unknown/unresolved requests use a single ingress sliding budget600per60seconds with concurrent16, bounded no client-created buckets. Paired checks/increments are atomic. Empty inactive buckets are pruned, cap4096active identity/customer buckets; when full return Limited with no eviction of another customer's active state. Synchronous bounded request parsing and policy resolution occur before scoped admission; neither loads content. Only unknown/unsupported identity or unresolved scope uses ingress rate/concurrency buckets. A resolved grant, including read-denied flags, uses only its paired identity/customer buckets; it is never charged against another customer’s global ingress budget. Admission reservation lifetime ends on cancellation/error/success; rate timestamps stay until window expiry.

Cursor binding: trusted identity kind/ID, security revision, scope, resource kind, assessment/report, manifest digest, page size, next authorized ordinal position, expiry300seconds from creation. Final page carries null. Continuation cannot extend original expiry; new handles for subsequent pages inherit the first chain expiry. Existing cursor remains repeatable until expiry; registry capacity is bounded128identity/512customer and global4096. Expired/invalidated entries are purged; no arbitrary client keys become registry partitions. On current policy revision change, invalidate associated handles. Registry mutations and quota operations share the B-owned synchronization fence so invalidation, duplicate read and cancellation cannot leak capacity. Reserve next-handle capacity before completion audit, then publish handle only after successful audit within TryCommit; release reservation on false/throw/cancel and audit the actual Limited outcome when full. Never record Success when next-handle admission fails. No cursor survives a new harness instance. Previous/new report lookup remains exact by requested version; current run is absent.
