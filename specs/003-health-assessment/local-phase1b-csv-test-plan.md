## Fixtures, limits and non-author review

Only versioned fictional saved task/source/artifact-review fixtures in a fresh dedicated loopback synthetic database. Use hostile strings solely as test inputs; no customer values, real One Identity SQL/code, provider key, deployed identity or shared cluster/role changes. Do not alter historical fixture/golden bytes. Preserve exact consumed inputs, source/runtime closure, native invocation/log/exit/results and non-author review before worktree cleanup; record failures/corrections distinctly.

The implementation checkpoint freezes exact trusted-server localhost origin/link navigation, module-owned supplied-transaction export capture, metadata schema/canonical input bytes/distinct output digest/receipt cell parity, bounded worker settings, audit producer/storage adapter and new flag/profile/database prefix before independent workers code. Limits are local fixture guards, not invented production capacity or SLA. Execute boundary-at-limit/over-limit and owned-process timeout/memory/resource isolation tests. Current approved product-scale NFRs and supported Windows/manual screen-reader/zoom checks remain independently unverified unless actually run.

Manual probes verify representative downloaded bytes open as literal metadata in a spreadsheet and protected links neither grant authority nor bypass fresh access checks. Record product/version/platform and interpretation result; no claim covers an untested spreadsheet. Automated literal bytes/formula corpus remains required even where a manual application is unavailable. User-saved-file deletion/revocation is explicitly outside product custody and is not a passing system-control claim.
