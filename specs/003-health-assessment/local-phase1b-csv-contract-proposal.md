## Snapshot and closed columns

Export reads actual verified saved Cycle14-compatible tasks, current source and attestations through a new owning-module read-only export-capture API that joins the caller-supplied connection, transaction and shared run fence. This API evaluates export-specific Consultant/Auditor authority separately from the unchanged Consultant-only task mutation policy; it never impersonates a Consultant or broadens existing Read/Create/Manage/Comment authority. Do not call an independent-connection ReadAsync while holding the supplied fence. The module owns integrity/source reads and returns only the authorized minimized immutable capture; the coordinator freezes its exact private API before code. It cannot seed tasks, repair corrupted records or substitute generated fixture data for a missing saved proof. Each run's complete export metadata is immutable once captured. A digest is a content binding, never authority.

Proposed ordered columns:

`csv_contract_version`, `run_id`, `task_id`, `finding_id`, `package_id`, `scoped_option_id`, `assignee_id`, `task_revision`, `task_status`, `plan_freshness`, `created_at_utc`, `planned_at_utc`, `current_source_digest`, `planned_source_digest`, `export_snapshot_digest`, `task_link`, `finding_link`.

IDs and assignee are opaque synthetic identifiers, never names or emails. Times come from accepted stored events in UTC. Task status is the saved workflow state; freshness is independently derived from verified current source and selected attestations. A Completed task remains Completed even if NeedsReconfirmation; export cannot imply validated remediation. Neither task completion nor export changes findings, scores, maturity, artifact review, reports or source availability.

The metadata envelope binds scope/run, exact saved baseline/profile/application/task/export contract versions and digests, complete current source binding, selected current attestation event/revision vectors and the ordered minimized rows. Sort rows by task ID ordinal; reject duplicate identities. The snapshotDigest (shown as export_snapshot_digest in each row) hashes deterministic minimized canonical input-envelope bytes with its own digest field empty; the implementation contract freezes canonical bytes and literal independent goldens. No reason/comment/artifact text enters the envelope. Permitted source digests may bind original content without carrying that content.

The user inspects count, run/version/snapshot identity, statuses and freshness before explicitly requesting export. A NeedsReconfirmation warning travels in the preview and explicit freshness column. Existing tasks whose current finding is Rejected remain exportable historical planning metadata when source/history integrity and current authority are valid; no conversion/reconfirmation occurs. A missing or unverifiable source denies export rather than degrading silently to a different column/view contract. Header-only output is identified as zero tasks, never healthy coverage or completed planning.

## Protected links and authorization

The trusted application constructs absolute first-party links that resolve from a saved standalone CSV, using one fixed accepted application origin from trusted server configuration and validated run/task/finding IDs. The local engineering contract must freeze the exact localhost origin, same-origin task/finding navigation shape and ID encoding before coding. If no accepted origin exists, export is denied. Neither request Host/forwarded headers nor client base URL, supplied hyperlink, storage locator, query language or external scheme can choose or change that origin/navigation. Closed validation rejects userinfo, off-origin redirects, scheme changes and encoded path/query substitution. This is private local navigation, not a new public backend contract. These links address the canonical scoped task/finding view, not raw evidence, files, artifacts, share tokens or a new public API.

Opening a link performs fresh identity/assignment/resource/category/policy/retention checks before lookup/serialization. Missing, expired, deleted or denied targets reveal only the existing generic denial/unavailable behavior; no cached export grant is reused. Navigation resolves authorized metadata and cannot broaden evidence permission. CSV links remain literal data cells, with no spreadsheet HYPERLINK formula. An exported file is not proof of continued access or an approved remediation instruction.

Policy is server-supplied. Require authenticated active nonrevoked named actor, exact active customer/project/environment assignment, permitted Consultant/Auditor role, explicit task.export, customer export policy, every task/category/resource grant and available nondeleted unexpired source. Auditor needs the additional scoped export grant. Other roles, workers acting as interactive users, wrong IDs/scopes and client-supplied authority are denied before content read. If authority cannot cover the complete run snapshot, deny the whole export rather than emit an undisclosed partial set or unauthorized counts. A local read-only Auditor fixture is separate from Cycle14's Consultant-only task mutations and does not grant task write authority.

## Rendering and delivery boundary

The interactive application captures/validates/enqueues an opaque scoped work identifier. The application prepares a minimized immutable envelope for that job; the renderer receives only that envelope and one declared output pipe/target. A separate process/container runs nonroot with read-only filesystem, no network, database, credentials, environment secrets or arbitrary filesystem mounts. It cannot obtain a canonical-read identity or act on links. Fixed limits cover envelope/row count/field bytes/output bytes, wall time and memory; exceeding them returns typed failure with no partial delivery. These synthetic engineering limits must be frozen/tested before coding and make no product-scale acceptance claim.

Encode valid Unicode as UTF-8 without BOM; use CRLF records and a fixed header. Quote every cell and double embedded quotation marks. Reject unpaired surrogates and disallowed control characters. For every textual cell, detect formula triggers `=`, `+`, `-`, `@` after leading whitespace; prefix a single apostrophe to the complete value before CSV quoting when triggered. Reject tab/CR/LF/NUL in metadata fields rather than allow control-led formula or extra-row ambiguity. No formula or active hyperlink is generated. Stable IDs/statuses/digests/links have closed validated shapes; decimal revision/time fields use invariant forms. Independent literal byte goldens and spreadsheet interpretation checks verify the normalization instead of relying on quoting alone.

snapshotDigest binds the minimized canonical input; a distinct outputSha256 binds the exact rendered CSV UTF-8 bytes. Never compare the CSV hash with the input-envelope hash. A metadata-only render receipt binds both digests, contract/version, row/header counts and complete cell parity. Before access, validate every ordered header/cell against the frozen minimized input using the independently specified encoder rules and validate the full expected literal output bytes; counts or a self-reported digest alone cannot establish correct rendering. The actual outputSha256 is computed by the trusted output verifier, not accepted on the renderer’s assertion. Current task/source/selected-attestation revisions, assignment, policy and availability are rechecked under the owning fence before delivery starts. A change after capture gives SourceConflict or denial, disposes bytes and requires fresh inspection; it never silently renders a newer snapshot. Delivery labels the file with the frozen snapshot identity. The access authorization linearization point is immediately before the first byte; cancellation/revocation notification can stop a live transfer, but bytes already delivered cannot be recalled. No claim of continuous authority after delivery is made.

A fresh request renders its inspected expected snapshot. Retry can return the same bytes only when that exact snapshot remains current and authorized; otherwise it conflicts. Rendering has no task-side effect. Repeated access is separately audited; do not invent durable payload caching or a reusable success token. Audit records bind opaque request/job/actor/scope/run, approved version/snapshot/output digests, counts, trusted UTC, decision/outcome and typed reason category. No CSV rows, links, comments, reasons, source/artifact content or credentials enter logs/audit. Required audit failure denies dispatch/delivery; a renderer failure or truncated output produces no successful-delivery record.

## Retention, compatibility and rollback

The product creates no durable export payload, export cache or retrieval endpoint in this slice. Transient processing is bounded to one request/job and is disposed on cancellation/timeout/process failure; no new retention period is selected. Source tasks/derived records continue their approved customer-selected retention classes and clocks. Export cannot reset them. The metadata-only audit follows the existing approved 12-month lifecycle, soft deletion, additional30-day purge and backup/tombstone rules; this slice does not claim deployed retention verification.

Before file delivery, show that the file contains a frozen planning snapshot, may become stale, remains subject to customer handling policy and cannot be remotely revoked after saving. User-saved files are outside product custody; no software deletion guarantee is implied. If later work stores/retrieves exports, it requires an approved artifact class/clock/access/deletion contract before activation.

The coordinator-composed new Phase1B profile includes the approved outcome/priority, automatic-AI and CSV contract locks; no separate CSV-only profile claims the single-run closure. Its dedicated flag uses a fresh guarded `iga_synthetic_` loopback database and existing module-owned source stores. No old schema/contract bytes, permissions, historical profile behavior or concurrent Phase1C routes change. Any additive metadata-only audit/work schema and exact startup database prefix must be justified/frozen in the implementation contract; this proposal grants no production migration. Rollback disables new requests/actions and preserves compatible source/history readers and approved audit records. No destructive down migration, purge or deletion of successful existing tasks is part of rollback.

## Alternatives and execution checkpoint

A filterable/full-content export would add data-selection and protected-payload policy surface, so it is deferred. Cached reusable downloads would require new artifact retention/access/revocation semantics, so the proposed local slice uses disposable delivery. Interactive in-process rendering would avoid a worker but conflict with ADR-0001 and is excluded. Omitting stale tasks would obscure historical planning work; explicit freshness preserves the complete selected current metadata snapshot.

After the owner's decision: record the exact approval; freeze internal schema/DTO/link/canonical/worker/audit/limit contracts with non-author review; assign isolated implementation/presentation/verification packets; execute [CSV test plan](local-phase1b-csv-test-plan.md); update canonical records and the private site through the coordinator. No runtime check, migration, export permission, full TP018/Milestone7/Phase1B/G1–G9 PASS follows from this preparation. Real source/provider/identity, customer use, deployed isolation, manual accessibility and production release remain separately gated.
