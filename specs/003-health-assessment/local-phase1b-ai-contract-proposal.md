## Observable local flow

An assigned fictional Consultant starts the new profile against its exact saved baseline. The screen shows locked deterministic and fake-AI work, base budget/current allowance, pending reservations, actual use and typed gaps separately. The worker evaluates fixed deterministic predicates, builds minimized configuration packets and automatically executes eligible AI work through the fake provider. Reading a screen or retrying a read never dispatches AI or creates budget/history rows.

Successful accepted proposals appear beside deterministic findings with an AI/Proposed label, declared fact/inference/assumption/missing-context/suggestion fields, uncertainty, exact packet-member citations and immutable provenance. Consultant review uses ordinary reasoned finding-review actions. Severe items remain prominent; current/provisional scores and the separate quality projection come from one verified saved source. The run remains an unpublished local assessment; Phase1C owns publication/report terminal behavior.

The bounded override form shows original limits, current allowance, hard ceiling, held/used amounts and the exact requested target. It requires explicit selection and a nonblank reason. If the worker has already committed terminal work, override is denied with a new-run explanation. An uncertain override response retains the exact command for explicit retry and then rereads current ledger state. No numerical default is inferred from another profile or an old saved run.

## Frozen fictional policy and budgeting

Proposed policy version: `synthetic-automatic-ai-policy-v1`. The fixture provider reports integer **fixture usage units**, not real tokens, dollars or estimates of OpenAI billing. For each dispatch, reserve 100 input plus 200 output units, total300. Known actual input/output must each be nonnegative and no greater than their respective reserved maximums. The benign fixture reports80 input plus160 output, total240. Other test outcomes supply explicit versioned actual counts, including known zero-use rejection before dispatch; counts are never inferred from response text. Out-of-bound usage is an integrity failure and retains the hold until an explicit valid reconciliation receipt, rather than saturating, dropping excess or declaring a PASS.

| Counter key, all within the resolved fixed synthetic customer | Initial allowance | Locked hard ceiling |
| --- | ---: | ---: |
| Customer/project/environment/run | 600 | 1200 |
| Customer/project/environment/run/category | 600 | 1200 |
| Customer/project/environment/fixture-period | 1200 | 1200 |
| Customer/project/environment/initiating-Consultant/fixture-period | 1200 | 1200 |

The period is a frozen opaque fixture epoch selected from the local versioned catalog, not wall-clock billing or a retention interval. Only the two run-specific allowance keys may be raised, to900 or1200. One atomic override declares both intended run and category targets; unchanged counters retain their current values, decreases and no-op overrides are denied. Period counters cannot be reset or enlarged through this action. Concurrent runs for that fixture epoch share their applicable period counters. A later profile revision/period is a distinct frozen fixture, never a reset of an existing run's accounting.

For every applicable counter, `actual charged + unresolved reserved + requested reservation <= current allowance` must hold under the same database transaction. Arithmetic is checked; malformed/missing scopes, unknown limits, overflow and incoherent ledger deny dispatch. Commit a durable reservation before leaving the transaction to call the fake provider. Never hold a database transaction across provider work. A lease and fencing generation ensure only the current worker may persist a result; lease recovery cannot invent a new provider attempt for a durable dispatched reservation.

Actual and reservation reconciliation updates all affected counters atomically. Immutable dispatch-attempt ID, logical provider idempotency key and usage receipt ID deduplicate receipts. An accepted repeated receipt returns its original result without another charge or release. A changed usage receipt, another attempt under the same ID or conflicting response digest is an integrity conflict. Retries count actual use from every known charged attempt; failed output does not get a free refund. Zero-used release requires an authoritative fake receipt saying no dispatch/no charge, never merely a network exception.

Override is authorized only for the fixed assigned Consultant with explicit AI budget-override action and category permission, active assignment, permitted customer/run AI policy and mutable resource state. The caller cannot supply the trusted actor or scope. Reason max2000 UTF-16 units, preserved exactly as inert domain text; invalid Unicode/nonblank/size/closed-field/revision checks occur before writing. Ordinary logs exclude the reason. Replays evaluate current authority/resource/category state before returning the original receipt; changed UUID reuse conflicts. An override does not release unknown reservations, change packet data, bypass scope policy, revise model/prompt versions, retry a terminal error or edit earlier events.

## Work, retries and unknown outcomes

The logical work key includes resolved scope, run, planned work ID and frozen packet/prompt/provider/policy/mapping identities. Attempts have separate immutable IDs and continuous attempt ordinals. The fake provider's idempotency key stays the same for retries of that logical work and binds the entire dispatched packet. Two packets cannot share it. At most three actual dispatch attempts are permitted. A lookup and an attempt replay identify the exact logical work key plus immutable attempt ID/ordinal and packet digest; an earlier attempt receipt is never substituted for an unknown later attempt. Repeating that exact attempt returns its original unchanged receipt. Only a known retryable no-result receipt permits the next attempt ordinal under the same logical work key. Fixture retry delay is fixed at zero in the deterministic test scheduler, with no claim about production backoff.

| Outcome | Ledger and persisted work | Next action |
| --- | --- | --- |
| Denied/disabled/not eligible before reservation | No dispatch or charge; payload-free denial; explicit terminal gap where authorized to describe coverage | Deterministic work continues; denied callers receive generic denial without coverage data |
| Budget exhaustion | No dispatch/reservation; terminal Not assessed with `AI_BUDGET_EXHAUSTED` | Deterministic work continues; later override cannot rewrite this result |
| Known valid response and bounded actual use | Reconcile charge/release; validate output and mapping; atomically commit immutable proposals, finding originals and AI coverage/checkpoint | Saved success is reused after restart/read/replay; no redispatch |
| Known response with rejected schema/citation/mapping | Reconcile known use; store digest/code metadata, no response payload or finding; terminal Error with `AI_OUTPUT_REJECTED` | New run/fixture correction; no automatic retry of structurally invalid output |
| Known rate limit/unavailability with explicit no-result receipt | Reconcile known use; record attempt failure | Retry same logical work within remaining budget/three-attempt bound; final Error `AI_RETRY_EXHAUSTED` |
| Timeout, lost response or process death after durable dispatch marker | Keep full reservation; record/restore Unknown outcome | One bounded fake-provider lookup using the exact logical key, unknown attempt ID/ordinal and packet; no new dispatch reservation |
| Lookup finds the original known receipt | Apply that exact actual/output receipt once, respecting worker fence and current eligibility | If work is not terminal, validate/commit original response; if terminal, billing metadata only |
| Lookup remains unknown or is unavailable | Keep reservation and visible unresolved-use marker; terminal Error `AI_UNKNOWN_OUTCOME` | A later exact lookup may reconcile billing only. A new run still sees shared-period holds; no silent release or duplicate proposal |
| Cancel/revoke/delete before dispatch | Cancel pending dispatch and release a known un-dispatched reservation atomically | No provider call or finding; authorized gap/failure metadata only |
| Cancel/revoke/delete after dispatch | Keep unresolved use or reconcile known use, deny proposal promotion/serialization under current policy | No late proposal commit; existing cancellation/deletion controls remain authoritative |

The fake lookup is part of the fixed provider test double, never a network resolver or raw-evidence endpoint. One lookup per recovery episode is bounded to one scripted result. Worker restarts can reread immutable receipts but cannot change the maximum dispatch count or conceal unknown use. Payload-free status distinguishes terminal AI coverage from unresolved billing; a complete-with-gaps projection can exist while a held reservation remains unresolved. Hard-kill/crash tests must cover reservation commit, dispatch marker, response arrival and transaction commit boundaries.

An empty valid proposal array charges its known use and yields terminal Not assessed with `AI_NO_VALIDATED_CONCLUSION`. It is visible successful protocol validation with zero findings, not a Pass or healthy-coverage claim. Missing normalization/redaction or contradictory required source produces Insufficient evidence without dispatch. Unsupported fixture compatibility produces Unsupported; excluded policy produces Excluded; inaccessible source produces Inaccessible; explicit source redaction produces Redacted. Every gap uses its responsible stage and authorized reference metadata; no planned unit is silently omitted.

## Proposal mapping, coverage and scoring

The new baseline supplies fixed immutable typed deterministic facts and normalized/redacted configuration records for the same fictional object inventory. An independently reviewed fixture map binds packet evidence IDs to object/module/category/outcome references and binds each allowlisted proposal ID to one planned AI rule-subject assessment unit. The expected plan enumerates a disjoint partition of deterministic-owned and AI-owned actual `CoverageKey(InventoryId, EvidenceCategory)` pairs before work. Use explicit distinct fictional inventory subjects/category assignments from the locked baseline: each pair belongs to exactly one execution owner, has exactly one terminal coverage result and exactly one `ScoringInput` unit with the matching CoverageState, including every gap. Only Pass/Finding units are eligible for health scoring; a gap unit remains represented for completeness/quality but adds no health denominator or penalty. Method, rule, work, proposal, dispatch or attempt identity never adds a third key component, another terminal result for the same pair or a dynamic denominator. Deterministic prerequisite evaluation for an AI-owned pair supplies packet facts only and emits no competing terminal coverage/scoring row. Shared object/category pairs cannot be assessed twice by inventing method-qualified IDs. The engineering freeze pins the exact inventory/category assignments, partition and literal plan/denominator before implementation, including accepted disjoint fixtures and denied overlap fixtures. It cannot derive its denominator from returned proposals. New application-version adapters preserve this existing key identity and historical validators.

Reuse the unchanged Cycle08 validators and limits: input64KiB/output256KiB, depth16, each string4096 UTF-16 units, 1–16 records, closed schemas, unique packet-member citations and declared-conflict uncertainty. The mapping adds no provider-controlled severity, confidence, authority, state, target, policy or fetch field. Trusted fictional catalog metadata supplies severity, likelihood/impact, confidence80%, positive weight1, category, root-cause signature and fixed original title/validation guidance. Each proposal must bind to exactly one planned unit; duplicate/foreign/missing bindings and citations unrelated to that unit reject the complete work result. An omitted planned proposal yields the no-conclusion gap. A future richer provider finding schema requires a separate reviewed version rather than silently extending Cycle08.

Preserve the model's declared fields as untrusted statements; a field named Facts does not certify factual correctness. Store exact accepted canonical packet and proposal bytes/digests in the owning synthetic domain records, full frozen run/source/mapping locks, provider/prompt/policy/attempt/usage receipt references and trusted UTC timestamps. Derive stable AI occurrence identity from scope/run/unit, never title, confidence, presentation edits or dispatch UUID. Retries cannot duplicate an occurrence or charge success twice. Different objects remain distinct occurrences; root-cause grouping may group only explicitly matching method/rule/signature and cannot collapse scored units or silently merge deterministic and AI findings.

All AI severities begin Proposed. Existing authorized Consultant/qualified-reviewer disposition semantics apply; the public role matrix is unchanged and the local host continues to supply its fixed synthetic identity. No AI auto-confirm flag is accepted. Generated originals and source/usage receipts stay immutable; edits/comments/confirm/reject/defer are append-only current-review overlays. Rejected units earn full weight, deferred/confirmed AI use the locked confidence factor, and proposed AI is excluded from publishable-current while included in provisional. Use unchanged `pilot-health-v1` severity factors, confidence clamp `[0.50,1.00]`, category renormalization, display rounding and red/yellow/green thresholds. Gaps affect quality and never improve/reduce default health. Informational AI has zero penalty and remains review-required. Maturity uses only separately evidenced indicator inputs; model statements cannot satisfy them.

Outcome adherence depends only on a separately locked approved outcome set from its owning module; an AI-inferred outcome is advisory and cannot approve itself. Until the coordinated outcome contract is approved and frozen, the AI fixture has no scored outcome links. Recommendations retain original references and unverified planning labels. Existing artifact/task approval eligibility is not broadened here; extending AI findings into those paths must preserve their exact approved source/review contracts in the coordinator's integration plan.

Current reads capture the full saved coverage, deterministic/AI originals, current review snapshot, ledger/result records and source/version locks through their owning-module APIs in one transaction under the same run fence. One complete immutable binding/digest identifies that captured source before fields or scores are exposed. Independently latest reads joined afterward, unfenced ledger/review lookups and fallback core scoring are prohibited; source/ledger/review writers join the same fence or an explicitly frozen compatible owning-module read protocol. The engineering freeze pins this composition and verifies concurrent writers yield one coherent before-or-after view. Missing/inconsistent source suppresses the affected projection with an unavailable marker, never cached success substitution. Hostile text stays framework-encoded text with no active links/HTML/Markdown execution. Read retry/selection/late-response fences cannot dispatch work or resurrect a stale source. Keyboard start/override/review/retry/history and320px reflow receive actual browser evidence; manual supported assistive-technology acceptance remains separate.

## Authorization, storage and compatibility

Follow accepted [ADR0001](../../architecture/decisions/ADR-0001-pilot-application-shape.md), [ADR0002](../../architecture/decisions/ADR-0002-pilot-tenant-isolation.md), [ADR0003](../../architecture/decisions/ADR-0003-immutable-evidence-and-publication-storage.md) and [ADR0004](../../architecture/decisions/ADR-0004-azure-pilot-technology-platform.md). The local fake callback has no untrusted-content executor; use existing modular APIs/worker/test host without introducing a production topology or claiming deployed isolation. A production AI gateway remains acceptance-gated under the existing architecture.

Only fixed synthetic evidence from the compatible immutable baseline enters packet creation. Evaluate active scoped worker authority, customer/run/category AI policy, source integrity, classification and resource availability at creation and again immediately before dispatch; repeat before output persistence/read. UI visibility alone never grants AI eligibility. Revocation/policy changes cannot be supplied by model output. Negative fixtures exercise foreign scope, stale assignment, unsupported schema/build, protected/raw/credential/free-text fields, category denial, soft-deleted source and policy-disabled resources. No real provider entry point is callable even with a configured credential.

Persist through an additive AI-owned schema only after explicit activation in a dedicated loopback `iga_synthetic_phase1b_` database. Existing migration bytes, eleven profile input envelopes, historical canonical contract bytes and old DTO omission rules must remain byte-compatible. New metadata fields are omitted when absent; full per-profile/source validators refuse missing or foreign locks rather than adopting current templates for old runs. The coordinator freezes exact flag/database ownership, module/project dependencies, schema/DTO/error shapes, canonical bytes and transaction composition before writing packets. No new dependency is justified by this proposal.

Use metadata-only ordinary logs/audit for policy, actor/job, stage, reservation/actual/override identifiers/counts, packet/output digest, validation code, proposal IDs and duration. Domain originals and authorized review/override history are distinct from operational audit and never copied to the private status site. Replay authorization comes before history/receipt serialization. Unknown/corrupt/deleted payload cannot be restored from logs or duplicate receipts. The existing retention/deletion policy governs later customer operation; this local proposal adds no clock, expiry, purge permission or retention exception. Synthetic tests can mark source/payload unavailable through an owned test boundary to verify references and denied serialization; they do not establish a production deletion workflow.

Rollback stops new dispatch/override/profile actions and retains a compatible reader for saved proposals, reservations, receipts and review history. Drain or reconcile owned dispatched work without clearing uncertain charges. No downmigration, truncation, budget reset, rewrite of old results or credential setup. Default macOS startup, supported manual accessibility, scale, deployed identity/isolation, provider configuration/ZDR, true token/cost latency and SEC-PILOT-004/G5/G1–G9 remain NOT VERIFIED.
