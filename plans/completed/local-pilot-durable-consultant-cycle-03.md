## Exact bounded contract and sequencing

1. Persist a value-free synthetic baseline plan, the complete explicitly synthetic input version tuple, declared gaps, immutable results, attempts, revision/checkpoint, lease, outbox and inbox in a module-owned PostgreSQL customer database. Start invokes the existing inventory planner. A fixed trusted synthetic scope is bound when the engine is constructed; mismatching scopes are refused before querying run data. This is an internal trusted-caller boundary, not implemented Entra authorization or customer routing.
2. Same project/start key and canonical input digest return the original run; changed inputs conflict. Additive digest-tracked migration refuses drift; it operates only on the explicitly bound synthetic database. PostgreSQL is canonical, with result+checkpoint+revision+outbox atomic commits, live generation/expiry fencing, revision compare-and-swap and immutable unique terminal results. A single run lease is sufficient here. Test fixture lease/retry timings are synthetic settings, not production defaults.
3. Run starts planned, worker acquires/runs, and durable coverage completion classifies Complete/CompleteWithGaps separately and advances to Scoring. Scoring is intentionally paused/unimplemented; neither kind claims overall assessment completion or health. Cancellation stops new work, permits already leased read-only work to finish within its lease, then preserves results in Cancelled. Recovery reacquires only expired leases and resumes missing units. Worker outcomes are explicit synthetic fixtures, never inferred healthy from applicability.
4. After durable checks, serve an actual React/TypeScript consultant view from a separate ASP.NET **local-demo-only** host. Fixed server catalog resolves named opaque scope/baseline/profile IDs. UI selects, starts, monitors, cancels, resumes expired work and reads durable history/locks/gaps. No uploads, arbitrary evidence, paths, SQL, weights, source credentials or customer identifiers are accepted. Full published assessment/review/report workflows are excluded.
5. Private demo transport: `/local-demo/v1/catalog`, `/runs`, `/runs/{id}`, `/runs/{id}/cancel`, `/runs/{id}/resume`. Strict versioned private DTOs; only catalog IDs/start request ID and revision/request ID mutations. Host binds 127.0.0.1 only, exact Host/origin checks, same-origin static build, antiforgery cookie+header, small JSON request limit, unknown properties denied, no CORS, CSP/self assets/no frames, API no-store and nosniff. No production identity or authorization bypass is shipped: the executable requires explicit synthetic mode and loopback-only PostgreSQL; no Entra sign-in or deployment manifest. Consultant cancel here is a synthetic demonstration operation; its production grant remains for exact public-contract/security review.

The lifecycle spec's coverage-completed wording is represented by the existing coverage completion kind, not a new overall Completed lifecycle state. Production operation shapes, baseline trust, scoped control-plane resolution and cancellation authorization remain approval/implementation dependencies; this packet grants none of them.
