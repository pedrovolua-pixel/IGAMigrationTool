# Internal reviewer decision bundle (pilot draft)

Normal artifact promotion requires independently attributable reviewer decisions for the exact artifact and scope. The `EvidenceGovernance` module now writes and verifies a strict, detached-signed metadata-only decision bundle. This is a local prototype; it does not grant a reviewer role, authorize activation or establish identity-backed trust.

The version `1` JSON object contains exactly `schemaVersion`, `artifactSha256`, `scopeId`, `reviewerId`, `role`, `decisionAt` and `decision`. The digest is 64 hexadecimal characters. Scope, reviewer and role are opaque uppercase identifiers (2–64 characters, letters/digits/hyphens); customer names and free text are rejected. `decisionAt` is explicit UTC. `decision` is `APPROVE` or `REJECT`. Extra or duplicate fields and bundles over 4 KiB are rejected. The writer emits the fields in deterministic order, and the verifier checks an RSA-PSS/SHA-256 detached signature over the exact bytes.

The caller supplies the expected artifact digest, scope and decision time. `ReviewerTrustRegistry` supplies reviewer identity, role, allowed scopes, public key, signing window and revocation status from protected configuration, never from bundle claims. An approval yields a short-lived in-process proof only after all checks pass. A signed rejection yields no approval proof. `ReviewEvidenceCoverage` requires every caller-configured role, exact artifact and scope, current verification, and at least one approver other than the artifact author. Its `CompleteForReview` result is not activation authority.

Production integration still needs identity-to-key enrollment, current role/assignment checks, a protected trust registry and revocation feed, restricted-store upload/retrieval, append-only audit, compatibility validation, and the separate owner-override path. These controls are required before SEC-PILOT-007 or an execution gate can close. See `architecture/decisions/ADR-0007-reviewer-decision-evidence.md`.

`NormalPromotionEvidencePreflight` combines the artifact/gate machine checks with freshly verified reviewer decisions and required-role coverage for one artifact digest and opaque scope. It rejects a missing, rejected, tampered, revoked, wrong-role or cross-scope review; a failed machine check short-circuits review. `ReadyForCompatibilityReview` means only that this evidence set passed its local checks. It does not establish compatibility, customer database-owner permission, an owner override, human activation, audit or pilot acceptance.
