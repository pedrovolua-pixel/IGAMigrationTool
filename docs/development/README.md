# Development documentation

The first implementation slice uses the SDK pinned in `global.json`. Install .NET SDK `10.0.401` and confirm `dotnet --version` reports that version from the repository root before running:

```sh
dotnet restore IgaMigrationTool.slnx --locked-mode
dotnet format IgaMigrationTool.slnx --verify-no-changes --no-restore
dotnet build IgaMigrationTool.slnx --configuration Release --no-restore
dotnet run --project tests/unit/EvidenceGovernance.Tests/EvidenceGovernance.Tests.csproj --configuration Release --no-build
dotnet run --project tests/unit/AssessmentCoverage.Tests/AssessmentCoverage.Tests.csproj --configuration Release --no-build
dotnet run --project tests/unit/CollectorSafety.Tests/CollectorSafety.Tests.csproj --configuration Release --no-build
dotnet run --project tests/unit/CollectorHost.Tests/CollectorHost.Tests.csproj --configuration Release --no-build
dotnet run --project tests/architecture/BoundaryChecks/BoundaryChecks.csproj --configuration Release --no-build
```

The synthetic checks exercise the internal digest/signature verifier and the [gate-check bundle writer, verifier, local trust registry and promotion machine-evidence preflight](gate-check-bundles.md), plus [signed reviewer decisions and role coverage](reviewer-decisions.md), [pilot-owner override evidence](pilot-owner-overrides.md), [Phase 1A coverage reconciliation](assessment-coverage.md), the [collector safety core](collector-permission-attestation.md), and the pilot-local collector host command/configuration/schedule contract. The caller must load trusted public keys from an approved source. A valid evidence result does not authorize a gate or artifact activation or satisfy SEC-PILOT-007. The partial `bootstrap-checks.yml` workflow runs these initial .NET checks, Bicep checks and a pinned Gitleaks directory scan of the checkout. The full change/merge, milestone and pilot-readiness gates in `specs/003-health-assessment/implementation-plan.md` remain unimplemented and unverified.

The `CollectorHost` project has a Windows Service entry point and fixed `status`/`collect-once` commands. Both run modes call the same local coordinator. A synthetic adapter tests pack/build/policy/permission admission, bounded pages, minimization, lease and encrypted checkpoint resume, including a staged page followed by checkpoint-write failure and idempotent retry. A separate process test forces termination while holding the lease and verifies reacquisition. An isolated encrypted page-stage primitive now verifies minimized content, stores it under an opaque context-bound filename and rejects tampering, changed replay and oversized pages; its synthetic key and directory do not represent a provisioned customer sink. The shipped adapter always returns `SOURCE_CONTRACT_PENDING` and cannot read SQL or stage a package. Its protected config and DPAPI key readers are Windows-only; local macOS/Linux tests cover the pure parser, schedule, local lease, encrypted checkpoint ledger, encrypted page stage and synthetic coordinator, while a `win-x64` self-contained publish checks cross-target packaging. [Partial bootstrap run 36868281712](https://github.com/pedrovolua-pixel/IGAMigrationTool/actions/runs/36868281712) passed protected-key/ACL cases and a self-contained service start/restart/stop smoke check on ephemeral GitHub `windows-2022` and `windows-2025` runners. Those checks are not a signed MSI, dedicated customer identity, Server Core, production sink or customer-host test. Customer-admin key provisioning/rotation, protected stage directory validation, aggregate retention, signed pack/policy loading, source permission probe, durable package sink and Windows crash/ACL behavior remain open. The executable is not an installer or customer release.

The local Gitleaks `8.30.1` directory scan completed with no findings on 2026-09-29. The workflow verifies the Linux x64 release archive SHA-256 before scanning and redacts any findings in its log. A directory scan covers the current checkout; it is not a history, provider-secret-store, or deployed-resource scan. Tool source: [Gitleaks release](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1) and [scan modes](https://github.com/gitleaks/gitleaks/blob/master/README.md#commands).

The repository generates a NuGet lock file for each .NET project and verifies it with `--locked-mode` in local and remote checks. It explicitly enables NuGet Audit for direct and transitive packages at the low-severity threshold. With `TreatWarningsAsErrors`, a known package advisory or unavailable audit source fails restore rather than appearing as a passing dependency check. This covers the .NET projects only; other ecosystems and OCI images need their own scanners when introduced. See [NuGet Audit](https://learn.microsoft.com/en-us/nuget/concepts/auditing-packages).

The architecture check scans declared `.csproj` references under `src/`. It rejects collector references into the server, renderer references into the server or collector, module references into hosts or collector, and host references into the collector. It also rejects missing/out-of-repository project targets and unsafe project XML. It does not inspect source-level imports, runtime service calls, browser code or Azure permissions; those boundaries need separate checks.

The partial engineering evidence-store Bicep module and its compile/lint/policy commands are documented in [`infra/bicep/README.md`](../../infra/bicep/README.md). No infrastructure deployment has been run.
