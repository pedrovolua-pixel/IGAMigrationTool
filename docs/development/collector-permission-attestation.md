# Collector permission decision (local safety prototype)

`CollectorSafety` contains a pure permission-decision function for the approved One Identity pilot source boundary. A future trusted SQL permission probe must report whether the query pack's minimum read set is satisfied and provide typed observed capability categories. This component opens no connection, executes no query, handles no credential, and enables no collector service or upload.

Minimum read permission with no excess is `Eligible`. Excess read-only permission is `EligibleWithWarning`; a caller must emit the prominent warning and payload-free audit before collection. Missing minimum-read proof, an absent/malformed probe, or any write, DDL, ownership, impersonation, security/server/agent administration, backup/restore or unrecognized category is `Blocked`. The result includes category identifiers only, never raw grants or SQL text. `BlocksEvidenceQueries` is a denial signal; a non-blocked decision alone is not authorization to run a query or skip the warning/audit path.

Seventeen synthetic cases exercise minimum permission, excess-read-only warning, missing proof, blocking categories, duplication and unknown inputs. The actual SQL permission probe, query-pack minimum-read definition, warning/audit integration, source access and customer database-owner validation remain unimplemented. Feature-001 C0 and health-pilot G2 remain open.

`PageCheckpointVerifier` is another pure local guard. It binds a candidate page to the expected query ID/version, exact build, scope, policy version and stable ordering key. Against completed immutable page metadata, the same boundary/digest is an idempotent replay; the same boundary with changed content is a conflict. Changed run context, malformed digest and corrupt completed metadata are rejected. Twelve synthetic cases exercise these decisions. The caller still needs encrypted durable checkpoint storage, atomic admission, actual page bytes/digest verification and cancellation/resume behavior.

`QueryApplicability` checks a trusted source-build claim against a reviewed query's exact build and module/version metadata. The comparison is ordinal and does not treat `10.x`, `*`, or `?` as an exact build. Missing and duplicate module claims fail input validation. A compatible result is only a metadata match: it cannot promote a pack, attest SQL safety or grant source access. Fourteen synthetic cases cover exact and mismatched builds, absent and changed modules, wildcard metadata and malformed discovery.

`PageBudget` computes a next-page upper bound from an approved page size, row cap and duration limit. It stops new pages on cancellation or exhausted limits and reduces the final permitted page to the remaining row allowance. The actual SQL command still needs bound paging parameters, timeout, cancellation, source-impact monitoring and explicit truncation/gap reporting. Twelve local cases exercise the boundary decisions.

`StaticSqlShapeValidator` uses the exact-pinned Microsoft T-SQL ScriptDom `180.107.0` parser (MIT license in its NuGet manifest) to fail closed on a small initial query shape: one `SELECT`, one approved schema/table, explicit approved columns, bound `TOP` page-size parameter, boundary parameter and column ordering. It rejects writes, multiple statements, `SELECT INTO`, wildcard fields, function/subquery evaluation, table/optimizer hints, joins, aggregation, XML output and unbounded pages. Parser diagnostics and SQL text are not returned. The package is needed because token or regular-expression filtering cannot reliably distinguish T-SQL statement classes. This structural result does **not** approve a query pack, prove field classification, enforce bound parameter values or validate production impact. The exact One Identity query pack remains unavailable, and no source connection exists.
