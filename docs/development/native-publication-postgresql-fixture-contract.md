## Purpose and governing contracts

Implement the reviewed publication store against real PostgreSQL using fictional protected source and authority records. Prove atomic visibility, immutable content, exact receipts, restricted logins, races and the session-held emission fence. This supplies M09 / Phase 1C engineering evidence needed before M11 / Phase 1D integration. It does not establish an eligible One Identity baseline, terminal product source, actual identity/provider permission, central audit integration, customer encryption, production grants, recovery or G6/G7/G8/G9 acceptance.

Source of truth: [native contract](../../specs/003-health-assessment/native-publication-v1-contract.md), [literal oracle](../../specs/003-health-assessment/native-publication-v1-oracle-addendum.md), [test plan](../../specs/003-health-assessment/native-publication-v1-test-plan.md), [implementation plan](native-publication-v1-implementation-plan.md), [ADR0001](../../architecture/decisions/ADR-0001-pilot-application-shape.md), [ADR0002](../../architecture/decisions/ADR-0002-pilot-tenant-isolation.md), [ADR0003](../../architecture/decisions/ADR-0003-immutable-evidence-and-publication-storage.md), [authorization matrix](../security/health-assessment-authorization-matrix.md) and [audit policy](../security/health-assessment-audit-policy.md).

`PostgreSqlPublicationTransactionV1` implements the existing transaction port internally. No connection, SQL command, schema name, role name or storage locator is a request input or public result. The methods above belong to the session except the named reconciler constructor/methods. Before AdmitAsync, the fixture authority calls exactly one matching Bind method with the already typed actor/command/request. It reuses existing core validation and CommandBytes/ReadRequestBytes, privately copies the original canonical bytes, computes its digest, and binds exact actor/scope/resource/operation-or-invocation identity once. A missing bind, changed actor/meaning, mismatched admission or second bind refuses. This is explicit constructor-injected operation context, never ambient actor authority or caller JSON. The bytes accompany SQL open/lookup functions below; SQL independently validates original shape/canonical hash and compares all actor/scope/operation/run/revision/source/warning or exact-report/request fields before admission/mutation. These internal additions do not change public core port signatures or golden bytes. The fixture admission uses persisted-seed/controller-owned original validity, not caller-supplied timestamps or an Allowed flag; the authority adapter owns its mirror solely to start conservative cancellation **before** backend/lock waits. SQL independently resolves current exact actor/session/security-version/action/role/condition/category/field facts under locks and verifies that the original admission ceiling is no later than its current allowed deadline. A stale/revoked mirror therefore cannot grant access. This test-only timer seam is explicit; it does not establish a production authority snapshot or distributed clock. No ordinary host receives the test friendship or source factory.

`AdmitAsync` starts one UTC/monotonic lease before any database connection/lock/admission wait: save original UTC cutoff and TimeProvider monotonic origin; elapsed budget is original cutoff minus trusted initial UTC, and expiry is the earlier of UTC cutoff and original monotonic-budget exhaustion. Link caller cancellation, reader-supplied lease tokens and session invalidation. A nonpositive budget refuses. `NarrowOriginalDeadline` may only reduce the original ceiling/budget, never reset origin or extend time; source metadata supplies retention before protected source loading, and exact report metadata supplies lifecycle/retention before blob/reference loads. Every source/store/audit/BlobStager connection, command, lock wait, verification and COMMIT acknowledgment uses `InvokeWithinOriginalLeaseAsync`, passes the linked token to Npgsql, races the dependency against that original deadline, and checks UTC/monotonic expiry before and after it. Late ignored dependencies cannot return data or mutate a disposed session. An unresolved write/COMMIT remains uncertain; cancel/discard the owning backend and confirm release before returning cleanup evidence. The frozen publisher currently passes only caller cancellation: **these adapter-owned mechanisms are new required fixture behavior**, not an existing core guarantee.

Publish fixtures retain Consultant, PublishWarningAcknowledged, exact actor/session/security-version/action and original recent MFA/CA evidence. Complete report read is an explicitly fictional complete-field fixture grant; current IdentityPolicy supplies no production mapping of all17 native fields. `CaptureAsync(transaction,actor,command,fence,ct)` checks identical session/context/actor/scope/fence bindings; obtains only minimized required-set/revision/retention-cutoff metadata without protected reference IDs/inputs/provenance; narrows the original lease; invokes current supplied fence for every category and all17 fields; then loads authorized SourceMetadataV1 plus protected fictional source bytes. Its decoder validates closed source/projection/score/inputs/retention/provenance commitments and defensively owns values. Metadata spies distinguish those steps. This is neither a client JSON endpoint nor an AssessmentRuns extension.

The reconciler is a **separate branch**, never a call to NativeReportPublisher/NativePublishedReportReader or ordinary Store.Begin. For reconciliation, freshAdmission is obtained from the trusted current authority owner for that new read-only invocation, binds the **same original command/request meaning**, and supplies that invocation’s conservative original cutoff. It cannot revive or extend the expired lease of the earlier write/emission; freshly current authority is separately evaluated, and the same still-expired actor denies. The reconciler computes/copies the existing original command/read-request bytes internally from its typed arguments. It opens a fresh nonpooled backend, executes `BEGIN READ ONLY`, acquires/rechecks fresh current authority and session locks with the original bounded validity owner, then calls only the read-only reconciliation signatures below. No business/context row INSERT, begin_write, finalization, blob/source load, successful/failed outcome append or COMMIT retry is permitted. Its read-only SQL signatures derive authority from exact actor/scope and the receipt’s minimized owning required-set/version metadata, check every current fact and held key on each call, and return original closed receipt/manifest/event control bytes only for a fully authorized Found. They use no writable context, GUC grant, prior-open Boolean or caller-selected lock proof. The internal parser verifies all original bytes/hashes, lifecycle, actor/scope, event action/outcome, command/request digest, original expected run revision/source digest and report/projection/score/manifest linkage. NotFound never releases receipt/version/event bytes. Valid Found receipts are strictly decoded and linked to the exact current authorized version/event/manifest and original command/request. Missing receipt/dependency/disposal uncertainty returns Unresolved, changed identity/meaning Conflict, corrupt commitment IntegrityMismatch, expired/current policy AuthorityDenied; every non-Found result has null Receipt. These results never become the core NotFound→capture/stage/audit path. Returning Found is metadata reconciliation, not report delivery or a newly published success. Delivery needs a new currently authorized exact-read invocation. No external command/API is added.

## Database identity and finite schema

Use a fresh named loopback fixture database per fictional customer, each with fixed `report_publication` and `report_publication_fixture` schemas. One database identity row binds schema version, migration digest and CustomerId; every scoped function checks it and `SESSION_USER` bindings. A second database proves customer separation and progress. No global content deduplication or arbitrary schema/database selection. PostgreSQL storage is a local immutable blob fixture, not the production encrypted object store selected by ADR0003.

Notation: `S` is `(customer_id,project_id,environment_id,assessment_id)` with nonzero UUIDs. Digest `D` is exactly 64 lowercase hex characters. Native revisions/sequence are positive signed64; lengths/counts are nonnegative signed64 with the frozen operation-specific bounds. Canonical bytes are `bytea`, never JSONB storage. Each unique/FK lookup has its matching composite primary/unique index; no cascading delete.

## Restricted logins, owners and migration

Provision separate actual local logins per fixture database: `rp_publisher`, `rp_reader`, `rp_audit`, `rp_blob_stager`, `rp_fixture_controller`, and explicit `rp_migration`. Tests may suffix these names to isolate concurrently owned databases; accepted names are seeded bindings, never runtime parameters. All execution logins are NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOREPLICATION/NOBYPASSRLS and have no membership in migration/function-owner roles. Credentials remain ephemeral local test inputs and never enter commits, receipts, logs or site.

Separate NONLOGIN owners own publication functions/tables and fixture-control functions/tables. Owners have only their exact DML requirements: immutable tables SELECT/INSERT, mutable heads/current projections SELECT/INSERT/UPDATE; no application owner DELETE on immutable tables. The fixture-context function owner may DELETE only its ephemeral backend context rows for cleanup; the publication-function owner may DELETE only its ephemeral consumed audit reservations. Neither may DELETE immutable business rows. A controlled migration identity owns the migration boundary and may assign ownership to these NONLOGIN owners. Only the isolated test provisioner may create fixture database/logins; migration001 itself creates no login, password, grant to an arbitrary existing application or startup execution.

Revoke PUBLIC schema usage, table/sequence access and function execution. Functions use `SECURITY DEFINER SET search_path=pg_catalog`; schema-qualified names only; fixed owner, explicit grants by full signature, no caller SQL or dynamic identifier. Revoke CREATE in PUBLIC, fixture and publication schemas from execution logins. Explicit default privileges for the owners deny PUBLIC on later functions/tables. SQL checks `SESSION_USER`, not `CURRENT_USER`, so SET ROLE cannot impersonate an approved login. Wrong binding, alternate login, missing ownership, schema drift or missing grant fails closed with fixed safe error categories.

| Login | Exact allowed surface | Must refuse |
|---|---|---|
| Publisher | Open/recheck fixture publish fence, minimized source metadata, authorized fake source load, receipt resolution, exact version metadata, successful Publish audit append, add publication/receipt; staged blob verification via BlobStager adapter. | Direct table INSERT/UPDATE/DELETE, source/authority/lifecycle mutation, read audit/history expansion, migration/DDL, foreign binding/scope. |
| Reader | Open/recheck exact fixture read fence, exact version/lifecycle/receipt metadata, authorized committed blob/reference reads, successful ReadExact audit and read receipt append. | Publication/source capture, blob staging or staged blob reads, publication receipt append, source/lifecycle mutation, direct DML/DDL. |
| Audit | Separate payload-free Denied/Failed/Cancelled outcome append on its configured stream; safe schema/actor-null/scope-null rules. | Successful publication/read event, report/source/blob content, receipt/version writes, lifecycle or binding changes. |
| BlobStager | Create-if-absent and verify immutable customer-scoped staged blobs, bound to configured scope. | Version/receipt/audit/source/authority data, replace/update/delete content, cross-customer existence/bytes. |
| FixtureController | Explicit fixture seed/mutate/clock helpers with shared mutation lock order except clock advancement. | Serving report content as a user; unregistered ordinary application activation. |
| Migration | Apply exact additive migration and controlled owner/binding seed in the new owned fixture database. | No use as publisher/reader/audit credential; no connection to existing customer or another worker's database. |

Successful audit writes occur on the publisher/reader's *same* transaction through tightly bound append functions and the original privilege lease. The separate Audit login writes only known failures after certain rollback/fence release, under its configured outcome binding and caller cancellation; it needs no expired user privilege to record a payload-free denial and cannot serve content. It is not a second transaction for successful audit. Native audit is its own event schema/stream; do not extend IdentitySessions' session event enum or emit AuthorityChanged for publication.

## Exact SQL function surface and grants

SQL names are `report_publication.<name>` (`p`) or `report_publication_fixture.<name>` (`f`). `SB` means `scope_bytes bytea`; `AB` means `actor_bytes bytea`; `CB` means `categories_bytes bytea`; `FB` means `fields_bytes bytea`. Each abbreviation expands to that literal named argument/type. These bytes are the closed canonical native four-UUID scope/four-field actor/sorted token arrays; admission retains their original bytes. A function never accepts a role/schema/deadline/time/head supplied by a product caller. Private validators/trigger functions have zero execution-login grants.

## Byte admission, Unicode, hashes and time precision

Keep original source/projection/score/manifest/audit/receipt bytes. PostgreSQL SHA-256 checks the actual `bytea`, not reserialized JSON. C# strict native codecs/readers perform full closed, duplicate, depth/size/link/set/Unicode validation. SQL repeats closed scalar/nested control schema, exact enums/UUID/counter/decimal-string/null meanings, sorted required sets, hash/length/binding and same-transaction linkage for command/manifest/score/audit/receipts before accepting restricted writes. Unknown schemas/fields, duplicate keys and canonical byte changes deny; JSONB equality alone cannot prove original bytes.

Report/source prose may include the frozen valid Unicode/control/NUL corpus. Never cast its payload bytes through PostgreSQL JSONB, text-unescape functions or a generic SQL canonicalizer: JSONB rejects escaped NUL, and text cannot store decoded NUL. Preserve it as bytea; source controller seeds its original independent commitments, source adapter strictly decodes under authorization, publication SQL checks all source-owned expected hashes, and exact reader verifies bytes again. A BlobStager SQL login can stage arbitrary opaque bytes only within bounds/hash integrity; that cannot create a visible report unless restricted publication/source/descriptor constraints match, and cannot authorize a read. Native metadata contains closed ASCII UUID/digest/version/category/field values; SQL control admission may use JSON/JSONB *after* duplicate and ASCII shape checks. Do not copy a session JSON canonicalizer over full report payloads. [PostgreSQL JSON documentation](https://www.postgresql.org/docs/current/datatype-json.html) explains the NUL and duplicate-key limitations.

SQL admission is a finite private algorithm, not general report JSON parsing. Exact fixture control refusal bounds: depth32; scope/actor control1KiB each; sorted category/field arrays, SourceMetadataV1, AuthorityControlV1, audit/receipt controls and each native manifest/score control1MiB. Native command64KiB/projection32MiB remain frozen. These bounds are engineering refusals, not customer performance acceptance. No SQL depth/size limit silently truncates inputs.

The adapter also owns a finite internal `NativeControlReaderV1` for returned manifest/audit/publication/read receipt and fully authorized fixture source-metadata control bytes: strict UTF8, original duplicate/type/key/enum/bounds checks via System.Text.Json (existing runtime), typed construction using existing core records, then byte equality to the corresponding core canonical encoder and full hash/link checks. It cannot parse arbitrary report payloads or instantiate a public source proof. The core has no raw metadata reader today; this adapter parser is explicitly new and independently tested against original control vectors.

Algorithm:

1. Reject SQL NULL, empty/oversize bytea, BOM, raw NUL and bytes outside permitted ASCII for **control** documents. `convert_from(bytes,'UTF8')` must succeed. Casting that retained original text to PostgreSQL `json` validates grammar while preserving duplicate entries; do not convert to jsonb yet. Full source/projection prose bypasses this control path and remains bytea.
2. Walk the `json` tree recursively using `json_typeof`, `json_each` and `json_array_elements WITH ORDINALITY`. At every object independently require exactly the declared case-sensitive key set, and `count(*) = count(DISTINCT key COLLATE "C")`; inspect occurrences before any jsonb conversion. Reject every missing/unknown/duplicate key, scalar type mismatch, array/object substitution, excess depth/size and JSON number (all native control numbers are canonical strings). `json_each` values preserve nested duplicates for the next recursion. Escaped aliases of a key still duplicate after decoding.
3. Select the closed schema by the **literal expected type at that function/field path**, never a caller-selected arbitrary schema. Scope/actor/createdBy/input/retention/provenance/warning/marker/artifact/metric records, seven-field command envelope, six-field read-request, manifest/audit/receipts, AuthorityControlV1 and SourceMetadataV1 reuse the exact frozen key/enum/type maps. Strings must match the grammar for that field: UUID lower-D/nonzero; D lowercase64; ASCII token bounded128; canonical signed64 string; decimal string0..100 with <=28 fractional digits and no exponent/trailing zero; UTC7 exact valid Gregorian calendar; nullable fields exactly their declared pair rules. Accepted control strings contain only permitted printable ASCII and have no quote/backslash/control/NUL. Control grammars reject Unicode escapes of arbitrary text or an opaque embedded JSON object; arbitrary prose is never admitted through these records. Schema constants and enums compare ordinally, not locale/case-folded. Values and SQL projections must match original bindings, counts and same-transaction rows.
4. Validate sorted sets and tuple identities from the decoded ordered arrays using COLLATE "C", rejecting duplicates rather than sorting them away. Preserve declared display order wherever a frozen control shape declares an ordered array. Native control documents contain only the closed metadata shapes above; projection/source text is not traversed by this SQL routine. Control manifest redaction/provenance/descriptor/category/field arrays follow the oracle’s literal order.
5. Render the admitted tree recursively: null→`null`; bool→`true`/`false`; allowed string→ASCII quote + exact decoded printable value + quote; array→`[` + child strings in retained validated order joined by `,` + `]`; object→`{` + (quoted exact key + `:` + child string) joined by `,` in key COLLATE "C" order + `}`. No whitespace/newline/normalization, JSONB serialization, text rounding or float conversion. Compare `convert_to(rendered,'UTF8')` byte-for-byte to the original bytea **before writes**, and verify SHA256(original)=supplied digest where present. Thus even whitespace, Unicode-escaped ASCII, escaped slash, numeric substitutions or different original key order refuse.
6. Only after these checks may private typed extraction/casts or jsonb lookup be used for convenient SQL projection. Store/hash the original bytea, never the projection. All exceptions map to fixed safe refusal categories. An invalid control input has no business/context/head mutation.

Independent admission controls include each root/nested duplicate (including escaped key alias), missing/unknown key, wrong string/bool/null/number, unsorted/duplicate set, overlong token, Unicode/control/NUL control value, malformed UTF8, canonical whitespace/key/escape differences, invalid seventh-digit calendar, counter/decimal boundaries and valid original native metadata bytes. The verifier writes SQL calls/expected refusals independently and checks all31 preserved originals including Unicode/NUL **payloads**. This algorithm is implementable with built-ins and separately reviewable; original codec goldens are never produced from it. Exact native bounds remain engineering refusals, not SLO acceptance.

PostgreSQL timestamps have microsecond precision, while native UTC7 has 100ns precision. Store canonical time text and exact signed64 .NET UTC ticks alongside a comparison timestamp; never round-trip canonical input timestamps through timestamptz. Parse the first six fractional digits into PostgreSQL time and add the seventh digit as ticks, validating the exact calendar representation. UTC tick origin is .NET0001-01-01, and input comparison ticks must equal the canonical text. Fixture clock returns its trusted text/ticks from SQL; no caller-selected audit timestamp. The deterministic fixture TimeProvider advances with that same controller-owned clock and independently preserves monotonic elapsed time; tests may simulate UTC rollback without rolling back elapsed time. Clock controls are fiction, not production time-sync evidence.

## Lock order and context lifetime

Execution connections use `Pooling=false` and remain pinned until fence disposal. Session and store share that one explicit backend. No nested second subject-lock connection. Blob staging and known-failure audit use separate bound logins/connections only where stated; neither acquires the authority/emission lock chain or waits on a lock owned by the caller.

The coordinator selected this actor-first mapping in governing amendment615e608; it refines the native order instead of claiming the draft’s prior customer-first order was equivalent. Runtime acquires applicable classes exactly as follows:

1. Stable actor subject/session shared session advisory key: `(CustomerId,TenantId,ObjectId,SessionId)`. **Exclude security version, authority revision and assignment revision** so revocation locks the same key as the old emitter.
2. Customer-policy shared session advisory key `(CustomerId)`; assignment/current policy resolution remains in this class.
3. Full assessment scope/source shared session advisory key S; source/assignment/category/report/reference mutation uses exclusive S.
4. Scoped operation/invocation transaction advisory key; unique receipt lookup serialized.
5. Owning source/current/version/lifecycle/reference rows in that fixed table order, UUID order within a table.
6. Audit-head row FOR UPDATE last; later append/event/receipt/version writes never reacquire an earlier class.

Actor revocation takes the stable actor/session key exclusive first. Customer-only policy mutation takes only the customer key exclusive and never requests actor keys. Scope-only mutation takes only S exclusive and never requests earlier keys. Any atomic mutation that actually spans classes takes the entire applicable actor→customer→scope→operation→rows→audit sequence. Multiple keys **within** a class sort by canonical UUID-tuple ASCII; no class inversion or wait-on-owned earlier lock is allowed. A controller clock advance takes no authority key because locks cannot freeze time. Tests observe independent backend wait/progress and prove actor revision changes do not move its lock key. Actual production/control/customer-plane revocation remains deferred.

Keys use signed64 `hashtextextended(fixed ASCII domain prefix + canonical lowercase UUID tuple,0)`, with domains `rp-v1:actor:`, `rp-v1:customer:`, `rp-v1:scope:`, `rp-v1:operation:` and `rp-v1:invocation:`. Tuple separator is `:` and UUIDs are lower-D; subject key includes all four stated UUIDs, scope includes all four S UUIDs, operation/invocation include CustomerId plus exact ID. Hash collision conservatively serializes and grants nothing. Authority/emission keys use session-level advisory locks; receipt keys use transaction locks. Track only owned keys, release reverse order, never unlock-all or return to a pool. Guards verify known locks before content; arbitrary built-in advisory unlock calls are possible but cannot grant access. [PostgreSQL locking documentation](https://www.postgresql.org/docs/18/explicit-locking.html#ADVISORY-LOCKS) distinguishes session and transaction lifetimes.

Adapter states are Created→Fenced→ActiveTransaction→PendingFinalized→CommittedReadOnly, or KnownRolledBack/Unknown→Disposed. These are one-invocation states; no successful-write reentry or COMMIT retry. The SQL context row is created in autocommit before business BEGIN. `begin_write` requires READ WRITE and Fenced, stores its own `pg_current_xact_id()` xid8 and immutable backend_start/login/TransactionId. Each Append/Add/source-write recheck requires ActiveTransaction, exact same current top-level xid and original context. `finalize_write` requires that same xid, repeats current full facts/deadline/linkage checks, changes state to **PendingFinalized**, and returns that state only. Every further Append/Add/finalize/begin-write call refuses, even before COMMIT. Caller supplies neither xid nor target state; no table write grants can forge them. A deferred guard requires PendingFinalized/current xid plus exact successful linked rows; skipping finalization cannot commit success.

PendingFinalized is not committed proof. `confirm_committed_readonly` and every committed-read function require `transaction_read_only=on`, the retained original xid, no equality to `pg_current_xact_id_if_assigned()` of the current transaction, and `pg_xact_status(original_xid)='committed'`. In-progress/prepared/aborted/unknown-too-old status denies. Thus a caller finalizing and switching its **still active original transaction** to READ ONLY cannot read as committed; forced early constraints cannot fabricate commitment. Confirmation happens in a newly begun READ ONLY transaction after COMMIT acknowledgment and sets only the C# verified state, without updating the context row. SQL rechecks proof on every retained read. [PostgreSQL transaction-status documentation](https://www.postgresql.org/docs/18/functions-info.html#FUNCTIONS-PG-SNAPSHOT) defines xid8 status and null-for-too-old behavior. Only transaction-context xid is inspected, never an arbitrary caller xid.

After proof, retained read methods are ReadDatabaseUtc/exact version/current reference/receipt methods; all writes/source loads/COMMIT attempts refuse. Row/writer locks finished at COMMIT; session authority/lifecycle/reference locks remain through emission. A fresh READ ONLY transaction provides current READ COMMITTED metadata rather than the completed writer snapshot. Known rollback invalidates the C# invocation before releasing its fence/outcome audit; rollback may revert the ephemeral SQL row to Fenced, but the disposed adapter never reuses it and closes the physical backend. Unknown invalidates the adapter and discards its backend without retry or new business/outcome writes; reconciliation uses a separately created READ ONLY backend with **no ephemeral context writes**. Dispose invalidates views and buffers, cancels pending work, confirms backend/known-lock release; uncertain cleanup never returns a pooled connection or a success.
