## Exact state and replay model

`state-replay-oracles.json` contains the explicit approved sequence cases. The current label is derived from the latest accepted event: no event → Unverified; latest withdrawal → Unverified even after refresh; latest review matching current source → Reviewed for planning; latest review for another source → Needs review.

Only a new accepted action changes artifact revision/history/accepted receipt. Fresh review is permitted from Unverified/Needs review, denied when already current. Withdrawal requires a current matching review; no-current/stale withdrawal is denied. Changing sources creates a versioned immutable source seed without resetting artifact revision or losing history. A conflicting payload under the same source seed identity fails integrity.

Authorized exact event replay returns its original immutable historical receipt with AlreadyApplied, including after later source/actions. It never restores a prior current overlay, changes revision/history or substitutes a fresh timestamp/actor. Current visibility and trusted current source are validated before disclosure; source unavailability or revoked/wrong-category/foreign authority denies even replay. A changed semantic command under the event ID conflicts; stale *new* commands conflict even if an old replay is permitted.
