# Independent local evaluation workflow verifier

Expectations are committed before inspecting the new domain, host or UI implementation. The selected identities/digests reuse the preexisting independent cycle03 oracle; the literal count vectors and named failure cases derive from the frozen cycle04 contract. No implementation-generated expected golden is accepted.

The standalone consumer exercises a dedicated guarded PostgreSQL18 fixture database through the public store API and independent SQL inspection. Separate browser/HTTP checks consume the explicitly enabled local host. It never grants actual reviewer authority, opens a real source or changes other owner databases. Initial failures, corrections, original expected bytes and final runtime evidence remain separately archived.

Run `python3 oracle.py` for the offline expectation checks. The oracle pins the literal expectation bytes committed before implementation review. Run the console project with `WF04_CONNECTION` pointing to a fresh, dedicated guarded database. `--tamper-only` intentionally corrupts a separate fresh database and checks failure closure. Main mode deliberately ends with revocation and schema drift; do not reuse or repair that evidence database for a clean rerun.

Independent executions against initial domain source `20e54b8` and fixture/transport `f53c2e1` plus startup guards passed 189 assertions, then 218 assertions in the expanded fresh-database run. These are overlapping executions, not a combined assertion count. A separate tamper-only database passed two assertions. The expanded run verifies literal selection/digests/count vectors, raw canonical SHA linkage, corrections, replay/conflicts, rollback, both final context flips, competing writes, concurrent exact replay, actual transaction-lock ordering with revocation, separate history authority, restart behavior, immutable SQL guards and drift rejection. Native logs and the intentionally altered databases are retained outside Git.

Browser/HTTP verification is tracked separately and remains pending final execution. Live identities, real source integration, queued cancellation, adjudication, retention/restore, manual accessibility and full Milestone08/G1–G9 remain open. Root canonical evidence records determine final source binding and current status.
