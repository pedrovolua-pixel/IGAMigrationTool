# Independent local evaluation workflow verifier

Expectations are committed before inspecting the new domain, host or UI implementation. The selected identities/digests reuse the preexisting independent cycle03 oracle; the literal count vectors and named failure cases derive from the frozen cycle04 contract. No implementation-generated expected golden is accepted.

The standalone consumer exercises a dedicated guarded PostgreSQL18 fixture database through the public store API and independent SQL inspection. Separate browser/HTTP checks consume the explicitly enabled local host. It never grants actual reviewer authority, opens a real source or changes other owner databases. Initial failures, corrections, original expected bytes and final runtime evidence remain separately archived.

Run `python3 oracle.py` for the offline expectation checks. The oracle pins the literal expectation bytes committed before implementation review. Run the console project with `IGA_SYNTHETIC_EVALUATION_DATABASE` pointing to a fresh, dedicated guarded database. `--tamper-only` intentionally corrupts a separate fresh database and checks failure closure. `--migration-only` leaves untracked migration metadata intact and checks that initialization refuses to adopt it; `--migration-recheck` repeats that denial on the preserved metadata without creating or modifying it. Main mode deliberately ends with revocation and schema drift; do not reuse or repair that evidence database for a clean rerun.
