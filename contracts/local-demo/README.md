# Private synthetic consultant demo contract v1

Authorized for [cycle 03](../../plans/completed/local-pilot-durable-consultant-cycle-03.md) coverage/recovery, [cycle 04](../../plans/completed/local-pilot-analysis-scoring-cycle-04.md) read-only synthetic analysis and [cycle05](../../plans/completed/local-pilot-review-maturity-cycle-05.md) opt-in synthetic review/history and independent maturity. This is a localhost fixture-host transport, not the production OpenAPI contract or an Entra/customer permission grant. Production contract and identity gates remain open.

`demo-v1.schema.json` is the strict DTO source. Generate the checked-in readonly TypeScript projection with `node contracts/local-demo/generate-types.mjs`; verify drift using `--check`. The host must serialize camelCase property names, exact PascalCase string enum values, UTC ISO timestamps, UUID run/request IDs and every required nullable field (use JSON null, not omission). Reject extra request properties; IDs resolve only against the fixed server catalog. Empty history and incomplete progress are valid; empty inventory cannot become perfect coverage. At `Scoring`, historical presets display **Coverage ready · scoring pending**; new analysis presets display **Coverage ready · local analysis**. `coverageCompletionKind` concerns coverage only.

| Operation                                 | Input                | Output                                                                                |
| ----------------------------------------- | -------------------- | ------------------------------------------------------------------------------------- |
| `GET /local-demo/v1/catalog`              | None                 | `Catalog`; initializes same-origin antiforgery cookie and returns request `csrfToken` |
| `POST /local-demo/v1/runs`                | `StartRunRequest`    | `RunDetail`, 201 new / 200 idempotent retry                                           |
| `GET /local-demo/v1/runs`                 | None                 | `RunHistory`, newest first, bounded server list                                       |
| `GET /local-demo/v1/runs/{runId}`         | Catalog-bound UUID   | `RunDetail`                                                                           |
| `POST /local-demo/v1/runs/{runId}/cancel` | `RunMutationRequest` | `RunDetail`                                                                           |
| `POST /local-demo/v1/runs/{runId}/resume` | `RunMutationRequest` | `RunDetail`; server permits only expired-lease recovery                               |

Mutations send JSON with `Content-Type: application/json` and `X-CSRF-TOKEN`; server requires same origin/cookie, a 4 KiB body maximum and strict DTO validation. Start deduplicates the same request ID and exact fixture selection; changed selection conflicts. Mutations check revision and server-controlled actions; stale writes return 409. Non-success returns `DemoError`, with safe explanation and nullable correlation/current revision. Use 400 malformed, 403 denied/CSRF, 404 unknown demo resource, 409 revision/idempotency/action conflict, 503 dependency unavailable. No route accepts fixture contents, arbitrary profiles/weights, paths, SQL, payloads or lease tokens.

`selection` labels come from the fixed catalog. `lockedInputs` carries value-free named immutable versions/digests; never credentials, data-plane locators or customer payloads. `actions` is authoritative; UI timestamps are explanatory only. Results/history/progress come from the durable engine; browser storage holds only the selected run ID. The separate read-only analysis projection calculates synthetic scores for compatible new presets; coverage alone never implies a score or full assessment completion. API no-store, loopback/Host/Origin restrictions, antiforgery, CSP and disabled production paths belong to the coordinator-owned host.

Cycle 04 adds `GET /local-demo/v1/runs/{runId}/analysis` → `AnalysisDetail`. Known runs return 200 with `Ready` or `Unavailable`, a nullable reason, exact `runRevision`, decimal score strings, original provenance and content digests; unknown UUIDs return the existing 404 error. Analysis is only available from fully reconciled canonical coverage for new named analysis presets with matching frozen contents and complete version tuple. Coverage-only, incomplete/cancelled, incompatible or changed fixtures expose no projection. The new read projection has no review/risk/publication mutation. `Scoring` remains the broader pending stage; local calculations do not claim a completed or published assessment. The DTO is private and does not approve production routes.

Cycle05 adds `GET /local-demo/v1/runs/{runId}/review` → `ReviewDetail` and `POST /local-demo/v1/runs/{runId}/findings/{findingId}/events` with strict `ReviewCommand` → fresh `ReviewDetail`. Only the two new review/maturity profiles permit writes. The server supplies the fixed synthetic actor, scope, assignment, category and action grants; clients never supply authority or originals. Per-finding revisions and exact event UUID/payload replay are enforced. Dispositions are Confirm/Reject/Defer from Proposed; comments and presentation edits preserve originals. Reject requires a reason. Unused command fields are null; bounded text is inert. Successful replay always rereads current history rather than sending an old outcome as current.

`AnalysisDetail.review`, `.maturity` and `.reviewSnapshotDigest` are required nullable additions. Older profiles return null for all three. New-profile current finding states/titles, health and quality come from one verified review snapshot; its digest matches the embedded review. Unverifiable review suppresses the current analysis. `AnalysisFinding.originalTitle` and `.initialState` preserve generated presentation/provenance. Independently frozen maturity carries versions, indicator/evidence/assessment references, ownership, threshold counts and limitations; health/review cannot promote it. These local DTOs supply no report, risk acceptance, validated closure or production public contract.

## Approved opt-in Phase1B composition

`--enable-synthetic-phase1b` adds the approved `synthetic-phase1b-combined-v1` profile only in a dedicated loopback `iga_synthetic_phase1b_` database. Its additive routes use closed 65,536-byte JSON, trusted host fixture authority, and the existing origin/CSRF boundary. Existing eleven profiles, generated deterministic DTOs, historical envelopes and migrations retain their original contracts. `src/web/src/phase1b-contract.ts` declares and validates the separate combined analysis DTO, including `AI` methods and provenance, rather than asserting the historical deterministic type.

The new frozen versions add literal `phase1bLocks`; null is omitted for historical profiles. Run start atomically locks explicitly selected exact approved outcome versions, creates the durable run and initializes its automatic fictional AI ledger. Scoring, review, guidance, fix artifacts and planning capture one verified source under registry then run fences. Planning presentation exposes the recorded complete objective map as `synthetic-phase1b-objective-map-v1`, its canonical factor-map digest, matches, exact guidance digest, assumptions, prerequisites and source references. Prior event history keeps its original source binding.

CSV inspection captures minimized immutable input; export rechecks authority and every owning source immediately before delivery. The pure isolated renderer cannot access the database. The session fences cover audit commit through response write. `Delivery` records authorized access, not confirmed client receipt; interrupted writes append the exact bounded `TransferInterrupted` denial. Protected navigation returns authorized task/finding metadata and denies stale or unknown targets. The Auditor fixture receives these narrowly granted read/export routes only. Downloaded copies contain protected identifiers and cannot be recalled after expiry or revocation.

The approved proposals, [engineering composition](../../specs/003-health-assessment/local-phase1b-engineering-contract.md), and phase-specific test plans define the exact local contract; this introduces no production identity, customer approval, live AI or report publication.
